# 인력할당 오프라인 CLI·GUI

사람별·사업별 연간 할당 목표를 월별로 배분하는 Python CLI와 데스크톱 GUI다. 입력한 연간 목표를 유지하면서 월별 가용량, 휴직, 사업 기간, 제외 월, 사업별 연간 배정 상한을 검증한다. 오류가 있으면 최종 할당표를 출력하지 않는다.

Python 3.10 이상과 PyYAML 6.0.3, 엑셀 저장용 openpyxl 3.1.5(의존성 et-xmlfile 2.0.0)를 사용한다. GUI는 PySide6-Essentials 6.12.0(의존성 shiboken6 6.12.0)을 추가로 사용한다. CLI는 Python 3.12, GUI는 Python 3.14·Windows 11에서 검증했다. 실행 시 인터넷이나 서버는 필요하지 않다. 그래프, CSV 출력, 연간 목표 자동 결정은 후속 범위다.

## 설치

저장소 루트에서 실행한다. 온라인 설치:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

오프라인 설치용 파일은 대상 환경과 같은 Python 버전·운영체제·CPU 환경에서 먼저 준비한다:

```bash
python3 -m pip download --only-binary=:all: --no-deps -r requirements.txt -d .wheels
```

저장소와 `.wheels` 디렉터리를 대상 환경으로 옮긴 뒤, 외부 패키지 인덱스 없이 설치한다:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --no-index --find-links=.wheels -r requirements.txt
```

Windows에서는 `python3` 대신 `python`, `.venv/bin/python` 대신 `.venv\Scripts\python.exe`를 사용한다. wheel은 환경에 맞게 다시 준비해야 하며 `.wheels`와 `.venv`는 Git에 포함하지 않는다.

GUI도 쓰려면 위 명령의 `requirements.txt`를 `requirements-gui.txt`로 바꿔 설치한다. 이 파일은 CLI 의존성을 포함하며, 오프라인 wheel도 같은 방식으로 준비한다. CLI만 쓰는 환경에는 PySide6가 필요 없다.

## 실행

저장소 루트에 동작 가능한 예제 `projects.yaml`과 `people/people_2027.yaml`이 있다. 실제 업무 데이터로 교체하기 전에 예제로 실행할 수 있다.

```bash
.venv/bin/python src/main.py people/people_2027.yaml
.venv/bin/python src/main.py people/people_2027.yaml --person 홍길동
.venv/bin/python src/main.py people/people_2027.yaml --project 사업1
.venv/bin/python src/main.py people/people_2027.yaml --all
```

사업 파일은 **현재 실행 작업 디렉터리의 `projects.yaml`**이다. 사람 파일 경로는 위치 인자이며, 관리 연도는 파일명이 아니라 파일 안의 `year`에서 읽는다. 조회 옵션은 한 번에 한 가지만 사용할 수 있다.

### 실행 스크립트

설치 후 Linux Bash에서는 `run.sh`, Windows PowerShell에서는 `run.ps1`을 사용하면 가상환경을 직접 활성화하지 않아도 된다.

```bash
./run.sh people/people_2027.yaml --all
```

```powershell
.\run.ps1 people\people_2027.yaml --all
```

인자가 없으면 사용법을 표시한다. 활성 가상환경(`VIRTUAL_ENV`)이 있으면 그 환경의 Python을 사용하고, 없으면 스크립트가 위치한 저장소의 `.venv`를 활성화한다. 가상환경 생성과 패키지 설치는 위 설치 절차로 먼저 진행한다. 전달한 인자와 프로그램 종료 코드를 그대로 보존하며, 실행 작업 디렉터리도 유지한다. 예를 들어 `templates/01_basic`에서 `../../run.sh people/people_2027.yaml --all` 또는 `..\..\run.ps1 people\people_2027.yaml --all`로 해당 템플릿을 실행할 수 있다.

옵션 없는 기본 출력은 검증 결과와 개인별·사업별 연간 요약이다. `--person`·`--project`를 지정하면 전체 요약은 생략하고 선택한 대상의 상세만 출력한다. 입력 파일·관리 연도와 검증 결과는 계속 표시한다. `--all-people`은 모든 개인 상세만, `--all-projects`는 모든 사업 상세만 표시하며 두 옵션 모두 전체 요약을 생략한다. `--all`은 전체 요약, 모든 개인 상세, 모든 사업 상세를 차례로 출력한다. 각 요약과 개인·사업 상세 앞에 빈 줄과 구분선을 표시한다. 개인 상세는 1~12월·연간 집계와 공백을 표시한다. 분기별 열은 표시하지 않으며 분기 합계의 내부 검증은 유지한다. 사업 조회는 월별 할당 합계와 연간 배정/할당/잔여를 표시한다. 수량은 모두 소수점 5자리다. 성공·경고만 있는 경우 종료 코드 0, 입력·계산 오류는 1, CLI 사용법 오류는 2다.

예제의 연간 요약:

```text
김철수: 0.75000 / 0.25000 / 1.00000
홍길동: 1.00000 / 0.00000 / 1.00000
사업1 (연구 지원 사업): 1.50000 / 0.60000 / 0.90000
사업2 (운영 사업): 1.50000 / 1.15000 / 0.35000
```

입력 YAML은 UTF-8(BOM 허용)을 권장하며, Windows 메모장의 ANSI 등 CP949로 저장한 파일도 읽는다. 상세 규칙은 [데이터 모델](docs/data-model.md#공통-규약)에 있다.

사업명은 앞뒤 공백을 제거하고 중간 공백은 유지한다. 사업약칭은 앞뒤 공백을 제거한 뒤 내부 공백을 허용하지 않는다. 약칭의 중복 검사·참조·조회에도 이 규칙을 적용한다.

사람 또는 사업 전체만 조회하는 예:

```powershell
.\run.ps1 people\people_2027.yaml --all-people
.\run.ps1 people\people_2027.yaml --all-projects
```

Linux에서는 같은 인자를 `./run.sh`에 전달한다. `--person`, `--project`, `--all-people`, `--all-projects`, `--all` 중 한 가지 조회 옵션만 지정할 수 있다.

### 엑셀 저장

`--excel 파일.xlsx`를 붙이면 계산 결과를 엑셀 파일로도 저장한다. 조회 옵션과 함께 쓸 수 있으며, 엑셀에는 조회 옵션과 관계없이 전체 결과가 들어간다. 경로는 실행 작업 디렉터리 기준이다.

```powershell
.\run.ps1 people\people_2027.yaml --excel 결과_2027.xlsx
.\run.ps1 people\people_2027.yaml --person 홍길동 --excel 결과_2027.xlsx
```

| 시트 | 내용 |
| --- | --- |
| `검증` | 관리 연도, 입력 파일, `ERROR`/`WARNING` 건수와 이슈 목록 |
| `요약` | 개인별 연간 요약(사업·공백·합계), 사업별 연간 요약(배정·할당·잔여) |
| `개인상세` | 사람마다 사업·공백·합계의 1~12월·연간 표 |
| `사업상세` | 사업마다 한 행: 배정·할당·잔여와 1~12월 할당 |

수량은 표시 형식 `0.00000`의 숫자 셀이며 합계는 수식이 아닌 계산 값이다. `ERROR`가 있으면 파일을 만들지 않는다. 같은 이름의 파일은 덮어쓰며, 엑셀에서 열어 둔 파일은 저장에 실패하므로 닫고 다시 실행한다. 상세 규칙은 [요구사항](docs/requirements.md)에 있다.

## GUI

`requirements-gui.txt`로 설치한 뒤 저장소 루트에서 실행한다. 인자는 없다.

```powershell
.\run_gui.ps1
```

```bash
./run_gui.sh
```

창 왼쪽 메뉴로 **입력** 화면과 **결과** 화면을 바꾼다(Ctrl+1 / Ctrl+2, `보기` 메뉴).

1. **입력** 화면에서 사업 파일과 사람 파일을 [열기]로 열거나 [새로 만들기]로 빈 입력을 시작한다. 사람 파일을 열면 같은 폴더나 바로 위 폴더의 `projects.yaml`도 자동으로 연다(예: `myteam/people/people_2026.yaml` → `myteam/projects.yaml`). 사업 파일을 직접 열었거나 편집 중이면 바꾸지 않는다.
2. **사업 입력**·**사람 입력** 탭에서 YAML 대신 표로 입력한다. **종합** 탭에서 전체 사람의 참여율을 한눈에 확인한다.
3. **생성 ▶**을 누르면 입력 화면의 현재 내용으로 계산하고 **결과** 화면으로 넘어간다. 저장하지 않아도 계산할 수 있다. 오류가 있으면 결과 화면의 검증 탭이 열린다.
4. [저장]·[다른 이름으로] 또는 Ctrl+S(모두 저장)로 YAML 파일에 저장한다. 저장한 파일은 CLI에서 그대로 쓸 수 있다.

| 화면 | 탭 | 내용 |
| --- | --- | --- |
| 입력 | 사업 입력 | 좌측 사업 목록(사업명·약칭·시작일·종료일·총 배정)과 우측 사업 × 연도 배정인력 표. 날짜는 달력에서 고르거나 `2026-03-01`처럼 입력 |
| 입력 | 사람 입력 | 관리 연도, 왼쪽 사람 목록, 오른쪽에 고른 사람의 참여 사업·참여율 표(사업 합계·공백·합계 자동 계산)와 휴직 기간(시작일·종료일·사유) |
| 입력 | 종합 | 사람 × 사업 참여율 전체 표(읽기 전용). 행을 두 번 누르면 그 사람의 입력 화면으로 이동 |
| 결과 | 검증 | `ERROR`(붉은 글자)·`WARNING`(주황 글자) 목록 |
| 결과 | 요약 | 개인별·사업별 연간 요약 |
| 결과 | 개인상세 | 왼쪽 목록에서 사람을 고르면 사업·공백·합계의 1~12월·연간 표 |
| 결과 | 사업상세 | 사업별 배정·할당·잔여와 1~12월 할당 |

**사업 입력** 탭은 좌우 두 표로 나뉜다. 두 표는 같은 사업이 같은 줄에 오고, 세로 스크롤과 현재 행(옅은 파란 띠)이 함께 움직인다.
- 좌측 `총 배정`은 그 사업의 모든 연도 배정인력 합계다. 보이지 않는 연도까지 더하며 편집할 수 없다. 형식이 틀린 값이 있으면 `?`로 표시한다.
- 우측 연도 열은 관리 연도 − 1부터 5개 연도이고, ◀ ▶로 한 해씩 옮긴다. 보이는 범위 밖에 값이 있으면 버튼에 건수가 붙는다(예: `◀ 2`). 관리 연도 머리글은 굵게 표시한다.
- 칸에 배정인력을 입력하면 그 연도 항목이 생기고, 비우면 지워진다.
- 맨 오른쪽 `YYYY 제외월` 열은 현재 칸이 있는 연도를 따라 제목과 내용이 바뀐다. 제외할 월을 `3,4,5`처럼 입력한다. 그 연도에 배정인력이 없는 사업은 입력할 수 없다.
- 칸 색: 회색은 사업 기간 밖 연도(생성하면 경고), 연보라는 제외 월이 있는 연도, 붉은색은 입력 확인 필요. 마우스를 올리면 내용을 보여 준다.
- 엑셀에서 복사한 사업 × 연도 범위를 Ctrl+V로 한 번에 붙여 넣을 수 있다.

**사람 입력** 탭은 사람별로 입력한다.
- 왼쪽 목록에서 [사람 추가]로 사람을 더하고(`새 사람`, `새 사람 2`…로 추가되며 바로 이름을 고칠 수 있다), 이름을 두 번 눌러 바꾼다. 비어 있거나 다른 사람과 같은 이름은 받지 않고 원래 이름으로 돌린다. 합계가 맞지 않거나 입력을 확인해야 하는 사람은 목록에서 붉게 보인다.
- 사람을 고르면 오른쪽 표에 그 사람의 참여 사업(사업·참여율·사업명)이 나온다. [행 추가]로 행을 더하면 사업 드롭다운이 열린다. 드롭다운에는 관리 연도에 배정이 있고 사업 기간이 그 해와 겹치는 사업 중 이 사람이 아직 고르지 않은 사업이 잔여 배정과 함께 나온다(예: `AI품질 — AI 기반 품질 예측 플랫폼 구축 (잔여 0.41000)`). [행 삭제]로 그 사업을 뺀다.
- 표 아래에 사업 합계·공백·합계가 나오고, 합계가 1.00000이 아니면 붉은 안내가 붙는다. 그 아래에서 휴직 기간을 입력한다.
- 엑셀에서 (사업, 참여율) 두 열을 복사해 붙여 넣을 수 있다. `사업명` 열은 자동으로 채워진다.

결과 화면 맨 위에는 관리 연도, `ERROR`/`WARNING` 건수, 생성 시각, 입력 파일 이름과 **엑셀 저장** 버튼이 있다. 생성한 뒤 입력을 고치거나 다른 파일을 열면 결과가 예전 입력 기준이라는 노란 안내와 **다시 생성** 버튼이 나온다. 생성하기 전 결과 화면에는 안내 문구만 보인다.

- 입력 표에서는 형식이 틀린 칸(날짜, 소수 5자리 초과, 약칭 공백·중복 등)을 붉게 표시하고 마우스를 올리면 고칠 방법을 보여 준다. 합계가 1.00000이 아닌 사람은 합계 칸이 붉다. 최종 판정은 **생성**의 검증 결과다.
- 입력 표는 엑셀에서 복사한 범위를 Ctrl+V로 현재 칸부터 붙여 넣고, Delete로 선택 칸을 지운다. 사업 약칭을 바꾸면 사람 참여율도 새 약칭으로 옮겨지고, 참여율이 있는 사업을 지울 때는 확인을 받는다. 사업 목록에 없는 약칭의 참여율은 지우지 않고 사람 입력 표에서 붉게, 종합 탭에서 `(미등록)` 열로 보여 준다.
- 저장하지 않은 입력이 있으면 탭 이름과 왼쪽 **입력** 메뉴에 `*`가 붙고, 다른 파일을 열거나 창을 닫을 때 저장할지 묻는다.
- **저장하면 파일을 새로 쓰므로 원래 파일의 주석(`#`)과 서식은 남지 않는다.** 대신 이번 실행에서 처음 덮어쓸 때 원본을 같은 폴더에 `파일이름.bak`(예: `projects.yaml.bak`)으로 백업한다. 표 편집기에서 다루지 않는 항목(알 수 없는 필드, 중복 키)은 열 때 알려 주며 저장하면 빠진다.
- 결과 그리드에서 셀을 골라 Ctrl+C를 누르면 탭으로 구분한 값이 복사되어 엑셀에 바로 붙일 수 있다.
- **엑셀 저장**은 CLI의 `--excel`과 같은 파일을 만든다.
- `ERROR`가 있으면 검증 탭만 보여 주고 엑셀 저장을 막는다.
- 마지막으로 열거나 저장한 파일은 다음 실행 때 다시 연다.
- 글자 크기는 기본 10pt이며 **보기** 메뉴 또는 Ctrl + `+`(Ctrl + `=`) / Ctrl + `-`로 7~24pt 사이에서 조절하고 Ctrl + `0`으로 기본값으로 돌린다. 바꾼 크기는 다음 실행 때도 유지된다.
- CLI는 작업 디렉터리의 `projects.yaml`을 읽지만, GUI는 사업 파일 경로를 직접 고른다.

Linux에서는 Qt 실행에 필요한 시스템 라이브러리(예: Debian/Ubuntu의 `libxkbcommon-x11-0`, `libxcb-cursor0`, `libegl1`)가 있어야 한다.

## 입력 템플릿

[templates/README.md](templates/README.md)에 권장 폴더 구조와 실행 방법을 정리했다. `templates/`에는 기본 배분, 여러 사람·사업, 제외 월, 부분 사업 기간, 휴직, 윤년, 다년 사업, 공백 처리, 경고·오류 등 17개 사례의 주석 달린 YAML 예제가 있다. 각 사례 폴더를 작업 디렉터리로 사용하며, `errors/`의 입력은 의도적으로 실패하는 참고 자료다.

## 구성

- `src/main.py`, `src/allocation/cli.py`: CLI 진입점과 조회 인자
- `src/allocation/loading.py`: 안전한 YAML 로드, 원문 숫자·중복 키·스키마 검증
- `src/allocation/models.py`: 입력·결과·진단 모델과 고정 소수 출력
- `src/allocation/flow.py`: 정수 최대 흐름 및 균등 초안을 참고한 재배치
- `src/allocation/engine.py`: 공백·허용 월 계산, 사전·사후 검증
- `src/allocation/rendering.py`: 진단·요약·상세표 출력과 공용 집계
- `src/allocation/tables.py`: 엑셀과 GUI가 함께 쓰는 결과 표
- `src/allocation/excel.py`: 엑셀(.xlsx) 저장
- `src/gui.py`, `src/allocation/gui.py`: PySide6 GUI 진입점과 화면
- `src/allocation/document.py`: 표 편집기의 입력 문서, YAML 읽기·쓰기, 입력 중 확인 (Qt 없음)
- `src/allocation/editor.py`: 사업·사람 입력 표 편집기 위젯
- `tests/test_allocation.py`: T01~T28·T30(편집기 문서 왕복), 경계 입력, 결정성, 완전 탐색 비교
- `tests/test_gui.py`: T29 GUI 동작, T30 입력 편집기, T31 입력·결과 화면 전환, T32 연도별 배정인력 표, T33 사람별 입력 (PySide6가 없으면 건너뜀)

## 테스트

```bash
.venv/bin/python -m unittest discover -s tests -v
```

표준 라이브러리 `unittest`를 사용한다. 모든 성공 fixture는 반복 실행과 YAML 항목 순서 변경 결과를 비교한다. 작은 정수 흐름 문제 200개는 완전 탐색과 비교하며, 외부 소켓을 금지한 상태에서 CLI도 검증한다. 테스트는 임시 YAML을 사용하고 예제 파일을 수정하지 않는다. GUI 테스트는 창을 띄우지 않는 `offscreen` 플랫폼에서 실행하며 사용자 설정(QSettings) 대신 임시 설정 파일을 쓴다.
