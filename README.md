# 인력할당 오프라인 CLI·GUI

사람별·사업별 연간 할당 목표를 월별로 배분하는 Python CLI와 데스크톱 GUI다. 입력한 연간 목표를 유지하면서 월별 가용량, 휴직, 사업 기간, 제외 월, 사업별 연간 배정 상한을 검증한다. 오류가 있으면 최종 할당표를 출력하지 않는다.

## 계획작업과 실적작업

- **실적작업**: 이미 결정된 사람별·사업별 연간 할당량을 가능하면 균등하게 월별로 나눈다. 월별 알고리즘은 구현되어 있으며 이번 업무 재정의에서 변경하지 않는다. 실제 월별 근무 기록을 입력한다는 뜻은 아니다.
- **계획작업**: 해당 연도의 사업 배정인력과 기간·제외 월·휴직 등을 고려해 사람별·사업별 연간 할당량을 정한다. 직전 실적 파일을 참고 자료로 활용하거나 새로 작성할 수 있다.
- 두 작업은 독립적이며 연초·연말은 업무 시점의 예일 뿐 실행 제한이 아니다. 외부에서 정한 연간 할당량도 바로 실적 입력으로 사용할 수 있다.

**2026-11-07 합의를 소스에 구현했다.** 상단에서 실적작업·계획작업을 선택하고 모드별 입력·결과 탭을 사용한다. 새 계획 형식은 `draft` 참고값·선택적 `priorities`·현재 결과 `allocations`이며, 확정 내보내기는 별도 폴더에 사업·확정 사람 파일을 함께 저장한다. 두 모드의 사업 자료·연도·편집 상태와 재시작 파일 목록은 독립적이다. 배포용 실행파일은 이번 변경으로 자동 갱신하지 않는다.

사용 순서는 다음과 같다.

1. 계획 연도의 사업을 정비한다. 종료 사업은 기록으로 유지하고 대상 목록에서 제외한다. 그 해 수행 사업의 배정인력이 없으면 계획 오류다.
2. 직전 사람 파일의 사본에서 `year`를 바꾸고 `stage: planning`으로 지정하며 `allocations`를 `draft`로 바꾼다. 사람·참여 사업·휴직을 정비하거나 새로 작성한다.
3. 계획을 계산·수정한다. `draft` 값의 대소관계가 기본 순위이며, 명시적 `priorities`가 있으면 그것을 우선한다. 참고값과 현재 결과를 분리하여 미완성·오류 상태도 중간 저장한다.
4. 현재 결과를 검증하고 별도 폴더에 `projects.yaml`과 `people/people_<연도>.yaml`을 함께 내보낸다.
5. 필요할 때 실적작업에서 확정 파일을 명시적으로 불러와 기존 월별 배분을 수행한다. 모드 전환만으로 자료를 자동 변환하거나 덮어쓰지 않는다.

용어 정의, 상세 절차, 파일 예시, 계산 규칙과 검증 경계는 [계획작업·실적작업 정의와 사용 절차](docs/annual-planning.md)에 정리했다.

Python 3.10 이상과 PyYAML 6.0.3, 엑셀 저장용 openpyxl 3.1.5(의존성 et-xmlfile 2.0.0)를 사용한다. GUI는 PySide6-Essentials 6.12.0(의존성 shiboken6 6.12.0)을 추가로 사용한다. CLI는 Python 3.12, GUI는 Python 3.14·Windows 11에서 검증했다. 실행 시 인터넷이나 서버는 필요하지 않다. 그래프와 CSV 출력은 후속 범위다.

## 설치

저장소 루트에서 실행한다. 온라인 설치:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

오프라인 설치용 파일은 대상 환경과 같은 Python 버전·운영체제·CPU 환경에서 먼저 준비한다:

```bash
python3 -m pip download --only-binary=:all: --no-deps -r requirements.txt -d .wheels
```

저장소와 `.wheels` 디렉터리를 대상 환경으로 옮긴 뒤, 외부 패키지 인덱스 없이 설치한다:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --no-index --find-links=.wheels -r requirements.txt
```

Windows에서는 `python3` 대신 `python`, `.venv/bin/python` 대신 `.venv\Scripts\python.exe`를 사용한다. wheel은 환경에 맞게 다시 준비해야 하며 `.wheels`와 `.venv`는 Git에 포함하지 않는다.

GUI도 쓰려면 위 명령의 `requirements.txt`를 `requirements-gui.txt`로 바꿔 설치한다. 이 파일은 CLI 의존성을 포함하며, 오프라인 wheel도 같은 방식으로 준비한다. CLI만 쓰는 환경에는 PySide6가 필요 없다.

## 실행

저장소 루트에 동작 가능한 예제 `projects.yaml`과 `people/people_2027.yaml`이 있다. 실제 업무 데이터로 교체하기 전에 예제로 실행할 수 있다.

```bash
.venv/bin/python src/main.py people/people_2027.yaml
.venv/bin/python src/main.py people/people_2027.yaml --person 홍길동
.venv/bin/python src/main.py people/people_2027.yaml --project 사업1
.venv/bin/python src/main.py people/people_2027.yaml --all
```

사업 파일은 **현재 실행 작업 디렉터리의 `projects.yaml`**이다. 사람 파일 경로는 위치 인자이며, 관리 연도는 파일명이 아니라 파일 안의 `year`에서 읽는다. 조회 옵션은 한 번에 한 가지만 사용할 수 있다.

### 가상환경 활성화

```bash
source ./venv.sh
```

```powershell
. .\venv.ps1
```

현재 셸에 저장소의 `.venv`를 활성화한다. 이미 이 환경이 활성화되어 있으면 그대로 유지하고, 다른 환경이 활성화되어 있다면 이 프로젝트 환경으로 전환한다. 직접 실행하면(`./venv.sh`, `.\venv.ps1`) 현재 셸 대신 활성화된 새 셸이 열리며 `exit`로 돌아온다. 가상환경이 없으면 먼저 위 설치 절차를 수행한다.

### 실행 스크립트

설치 후 Linux Bash에서는 `run.sh`, Windows PowerShell에서는 `run.ps1`을 사용하면 가상환경을 직접 활성화하지 않아도 된다.

```bash
./run.sh people/people_2027.yaml --all
```

```powershell
.\run.ps1 people\people_2027.yaml --all
```

인자가 없으면 사용법을 표시한다. 활성 가상환경(`VIRTUAL_ENV`)이 있으면 그 환경의 Python을 사용하고, 없으면 스크립트가 위치한 저장소의 `.venv`를 활성화한다. 가상환경 생성과 패키지 설치는 위 설치 절차로 먼저 진행한다. 전달한 인자와 프로그램 종료 코드를 그대로 보존하며, 실행 작업 디렉터리도 유지한다. 예를 들어 `templates/01_basic`에서 `../../run.sh people/people_2027.yaml --all` 또는 `..\..\run.ps1 people\people_2027.yaml --all`로 해당 템플릿을 실행할 수 있다.

옵션 없는 기본 출력은 검증 결과와 개인별·사업별 연간 요약이다. `--person`·`--project`를 지정하면 전체 요약은 생략하고 선택한 대상의 상세만 출력한다. 입력 파일·관리 연도와 검증 결과는 계속 표시한다. `--all-people`은 모든 개인 상세만, `--all-projects`는 모든 사업 상세만 표시하며 두 옵션 모두 전체 요약을 생략한다. `--all`은 전체 요약, 모든 개인 상세, 모든 사업 상세를 차례로 출력한다. 각 요약과 개인·사업 상세 앞에 빈 줄과 구분선을 표시한다. 개인 상세는 1~12월·연간 집계와 공백을 표시한다. 분기별 열은 표시하지 않으며 분기 합계의 내부 검증은 유지한다. CLI 사업 상세는 연간 할당이 양수인 참여자별 1~12월·연간 할당과 사업 월별·연간 할당 합계, 연간 배정/할당/잔여를 표시한다. 연간 할당이 0인 사람은 제외하며, 참여자가 없는 사업도 0인 합계 행을 표시한다. 엑셀의 사업상세 표는 기존과 같다. 수량은 모두 소수점 5자리다. 성공·경고만 있는 경우 종료 코드 0, 입력·계산 오류는 1, CLI 사용법 오류는 2다.

예제의 연간 요약:

```text
김철수: 0.75000 / 0.25000 / 1.00000
홍길동: 1.00000 / 0.00000 / 1.00000
사업1 (연구 지원 사업): 1.50000 / 0.60000 / 0.90000
사업2 (운영 사업): 1.50000 / 1.15000 / 0.35000
```

모든 인력 수량 입력은 소수점 아래 5자리까지만 허용한다. 배정인력·실적 할당량·계획 참고 점수와 결과에 모두 적용하며, `0.500000`처럼 끝에 0이 있어도 6자리 이상이면 오류다. 자동 반올림이나 잘라내기는 하지 않는다.

입력 YAML은 UTF-8(BOM 허용)을 권장하며 Windows 한글 ANSI인 CP949와 일반적인 EUC-KR 파일도 자동으로 읽는다. GUI에서는 인코딩을 직접 지정하고 원본 인코딩으로 저장할 수 있다. 상세 규칙은 [데이터 모델](docs/data-model.md#yaml-인코딩의-보관과-저장)에 있다.

양수 연간 목표가 있는 사람·사업은 허용 월에 균등하게 나누어 배정할 수 있는지 먼저 확인한다. 완전한 균등 배정이 안 되면 월별 합계를 지키면서 편차를 줄이고, 가능하면 각 월에 최소 `0.00010`을 유지한다. 이 하한도 모두 지킬 수 없을 때만 더 작은 값이나 0을 허용하고 해당 월에 사람·사업·배정량을 포함한 `W006` 경고를 표시한다. 나눗셈의 남는 `0.00001`은 가능한 경우 3·6·9·12월에 우선 배치한다. 연간 목표와 개인별 월 합계는 항상 그대로 지킨다.

사업명은 앞뒤 공백을 제거하고 중간 공백은 유지한다. 사업약칭은 앞뒤 공백을 제거한 뒤 내부 공백을 허용하지 않는다. 약칭의 중복 검사·참조·조회에도 이 규칙을 적용한다.

사람 또는 사업 전체만 조회하는 예:

```powershell
.\run.ps1 people\people_2027.yaml --all-people
.\run.ps1 people\people_2027.yaml --all-projects
```

Linux에서는 같은 인자를 `./run.sh`에 전달한다. `--person`, `--project`, `--all-people`, `--all-projects`, `--all` 중 한 가지 조회 옵션만 지정할 수 있다.

### 사람별 월 고정 배정

특정 사람의 사업 월별 값이 이미 정해졌다면 사람 파일의 `fixed`에 1~12월 값을 적는다. `allocations`에는 기존처럼 연간 목표를 쓰며 고정값 합계가 그 목표와 정확히 같아야 한다. `fixed` 없는 기존 파일도 그대로 쓴다.

```yaml
year: 2027
people:
  - name: 홍길동
    allocations: {사업1: "0.50000", 사업2: "0.50000"}
    fixed:
      사업2: ["0.08333", "0.08333", "0.08334", "0.08333", "0.08333", "0.08334",
              "0.00000", "0.00000", "0.00000", "0.00000", "0.00000", "0.00000"]
```

고정값에는 0과 월 최소치 `0.00010` 미만도 허용하지만 소수 6자리 이상은 거부한다. 고정 사업의 값을 예약하고 나머지 사업만 배분한다. 고정 합계 불일치는 E104, 제외 월·휴직·기간·월 가용량과의 충돌은 E105, 나머지 배분 불가능은 E201이다. 자동 보정하지 않는다.

GUI **실적 입력 → 사람 입력**에서 사람을 고르면 아래에 **월별 고정** 표가 항상 보인다. 참여 사업 표에서 사업을 고른 뒤 [선택 사업 월 고정]으로 추가하고 12개월을 직접 입력하거나 엑셀에서 붙여 넣을 수 있다(YAML에 `fixed`가 없어도 된다). [선택 고정 해제]는 잠금을 푼다. 저장·재열기에도 보존하며 고정 사업의 약칭·참여율 행을 실수로 다른 사업으로 바꾸거나 삭제하지 않도록 안내한다. 잘못된 수량과 합계는 입력 화면에서 고친 뒤 결과를 다시 열면 된다. 12개가 아닌 목록 등 구조 오류는 가져오기에서 알려 주고 기존 문서를 유지한다.

계획 파일은 fixed를 지원하지 않으며, 다음 연도 계획 준비에도 이전 월 고정값을 자동 복사하지 않는다. 자세한 규칙과 예제는 [데이터 모델](docs/data-model.md#실적-사람별-월-고정값-fixed), [고정 배정 템플릿](templates/18_fixed_months/people/people_2027.yaml)을 참고한다.

### 엑셀 저장

`--excel 파일.xlsx`를 붙이면 계산 결과를 엑셀 파일로도 저장한다. 조회 옵션과 함께 쓸 수 있으며, 엑셀에는 조회 옵션과 관계없이 전체 결과가 들어간다. 경로는 실행 작업 디렉터리 기준이다.

```powershell
.\run.ps1 people\people_2027.yaml --excel 결과_2027.xlsx
.\run.ps1 people\people_2027.yaml --person 홍길동 --excel 결과_2027.xlsx
```

| 시트 | 내용 |
| --- | --- |
| `검증` | 관리 연도, 입력 파일, `ERROR`/`WARNING` 건수와 이슈 목록 |
| `요약` | 개인별 연간 요약(사업·공백·합계), 사업별 연간 요약(배정·할당·잔여) |
| `개인상세` | 사람마다 사업·공백·합계의 1~12월·연간 표 |
| `사업상세` | 사업마다 한 행: 배정·할당·잔여와 1~12월 할당 |

수량은 표시 형식 `0.00000`의 숫자 셀이며 합계는 수식이 아닌 계산 값이다. `ERROR`가 있으면 파일을 만들지 않는다. 같은 이름의 파일은 덮어쓴다. 같은 폴더의 임시 파일(`.~*.xlsx`)에 다 쓴 뒤 바꿔 넣으므로 저장에 실패해도 기존 파일은 그대로 남는다. 엑셀에서 열어 둔 파일은 저장에 실패하므로 닫고 다시 실행한다. 상세 규칙은 [요구사항](docs/requirements.md)에 있다.

## GUI

`requirements-gui.txt`로 설치한 뒤 저장소 루트에서 실행한다. 인자는 없다.

```powershell
.\run_gui.ps1
```

```bash
./run_gui.sh
```

메뉴바 우측 끝의 `작업모드` 콤보 상자 또는 `작업` 메뉴로 **실적작업**·**계획작업**을 선택한다(Ctrl+Alt+1 / Ctrl+Alt+2). 각 모드에는 좌측 세로(서쪽) 탭의 **입력**·**결과**가 있다. 모드를 전환해도 입력·수동 결과를 유지하며 다른 작업 자료를 자동으로 변경하지 않는다.

상단 **파일** 메뉴는 `새로 만들기`, `불러오기`, `저장`, `실적 파일에서 계획 준비`, `내보내기`, `종료` 순서다. `실적 파일에서 계획 준비`는 계획작업에서만 활성화된다. Ctrl+S는 저장, Ctrl+Shift+S는 내보내기다. 계획 저장은 오류 상태도 중간 보존하고, 계획 내보내기는 검증된 현재 결과를 확정한다. 실적 모드의 저장과 내보내기는 기존 입력 파일 저장을 수행한다. 종료할 때는 두 모드의 미저장 변경을 모두 확인한다.

실적작업에서는 다음 순서로 사용한다.

1. **입력** 탭에서 파일 메뉴의 [불러오기]로 사업·확정 사람 파일을 연다(여러 개 선택 가능, 종류는 자동 판별). 사람 파일만 열면 같은 폴더나 바로 위 폴더의 `projects.yaml`도 자동으로 연다(예: `myteam/people/people_2026.yaml` → `myteam/projects.yaml`). 해당 모드의 사업 입력이 비어 있을 때만 찾는다. [새로 만들기]는 현재 모드만 비우고 올해 빈 연도로 시작한다.
2. **사업 입력**·**사람 입력** 탭에서 YAML 대신 표로 입력한다. **종합** 탭에서 전체 사람의 참여율을 한눈에 확인한다. 같은 연도 사람 파일은 합쳐지고 이름이 겹치면 그 파일은 건너뛰며, 다른 연도는 연도 목록에 따로 열린다. 연도 콤보·[연도 추가]·[연도 닫기]로 연도 문서를 고르고 더하고 뺀다.
3. **결과** 화면으로 가면 고른 연도의 현재 내용으로 바로 계산해 보여 준다. 내보내지 않아도 계산할 수 있다. 오류가 있으면 결과 화면의 검증 탭이 열린다.
4. 파일 메뉴의 [저장] 또는 [내보내기]로 폴더를 지정한다. 폴더에 `projects.yaml`과 연도별 `people/people_<연도>.yaml`을 쓰며 CLI에서 그대로 쓸 수 있다.

| 화면 | 탭 | 내용 |
| --- | --- | --- |
| 입력 | 사업 입력 | 좌측 사업 목록(사업명·약칭·시작일·종료일·총 배정)과 우측 사업 × 연도 배정인력 표. 날짜는 달력에서 고르거나 `2026-03-01`처럼 입력 |
| 입력 | 사람 입력 | 연도 콤보로 고른 연도의 왼쪽 사람 목록, 오른쪽에 고른 사람의 참여 사업·참여율 표(사업 합계·공백·합계 자동 계산)와 공백 기간(시작일·종료일·사유) |
| 입력 | 종합 | 사람 × 사업 참여율 전체 표(읽기 전용). 맨 아래에 사업별합계 고정 행(각 사업 열의 사람 합계와 전체 합계). 행을 두 번 누르면 그 사람의 입력 화면으로 이동 |

| 결과 | 개인상세 | 왼쪽 목록에서 사람을 고르면 사업·공백·합계의 1~12월·연간 표 |
| 결과 | 사업상세 | 왼쪽 목록에서 사업을 선택하면 오른쪽에 배정·할당·잔여와 참여자별 월·연간 할당 및 합계 표시 |

### YAML 인코딩 선택

- **불러오기** 창의 `읽기 인코딩` 기본값은 **자동 판별**이다. 파일을 선택하면 읽기 전용 미리보기로 한글과 판별 결과를 확인할 수 있다. 필요할 때 **UTF-8 / UTF-8 BOM / CP949 / EUC-KR**을 지정한다. 자동 판별을 다시 선택하면 해당 파일의 이전 직접 지정을 해제한다. 자동으로 찾는 사업 파일은 사람 파일과 별도로 판별한다.
- **저장·내보내기** 창의 `저장 인코딩` 기본값은 **기존 파일/원본 인코딩 유지**다. 기존 대상 파일이 있으면 그 인코딩을, 새 경로는 원본 인코딩을 유지한다. 새 문서는 UTF-8이며 서로 다른 인코딩의 원본을 합쳤을 때만 선택을 요청한다. 직접 고른 인코딩은 저장하는 묶음 전체에 적용한다.
- 화면 하단에서 사업·선택 연도 사람 문서의 인코딩을 확인하고 마우스를 올리면 파일별 상세를 볼 수 있다. CP949와 EUC-KR은 공통 바이트가 같아 완전히 자동 구분할 수 없다. 공통 바이트는 CP949, ASCII는 UTF-8로 처리하며 필요하면 직접 지정한다.
- 원래 인코딩으로 저장할 수 없는 문자가 있으면 해당 파일을 UTF-8로 바꿀지 확인한다. 거절하면 전체 저장을 취소하며 문자를 `?`로 바꾸지 않는다. 모든 파일의 변환이 끝난 뒤 묶음으로 저장하고 첫 덮어쓰기의 원본 `.bak`을 보존한다. 인코딩을 유지해도 원본 주석·서식은 보존하지 않는다.

### 계획작업

1. 상단에서 **계획작업**을 선택한다. 입력 탭에서 사업 파일을 별도로 불러와 계획 연도 배정인력·기간·제외 월을 정비한다. 종료 사업은 기록으로 남기고 그 해 후보에서 제외한다. 계획 연도 수행 사업에 배정인력이 없으면 참여자 유무와 무관하게 오류다.
2. 새 계획 파일을 불러오거나 **실적 파일에서 계획 준비**로 이전 실적 사람 파일과 새 계획 연도를 지정한다. 이전 할당값은 `draft` 참고 점수로 복사하고 원본·휴직 날짜는 바꾸지 않는다. 직접 사람을 추가해 처음부터 작성할 수도 있다.
3. 사람 입력에서 참여 사업·참고 점수·선택적 명시 순위·공백 기간을 편집한다. 참고 점수는 큰 값 우선, 명시 순위는 작은 숫자 우선이다. 하나라도 명시 순위를 입력하면 미기재 사업은 최하위보다 한 단계 아래 동순위다. 전부 비우면 점수 방식을 쓴다. 점수 0도 참여 대상이다.
4. **결과** 탭에서 [계획 계산 / 재계산]을 누른다. 사람 × 사업 연간 할당표를 직접 수정할 수 있고, 다른 셀은 자동 변경하지 않는다. 탭을 열기만 해서는 수동 결과를 덮어쓰지 않는다.
5. **저장**으로 미완성·오류 상태도 중간 보존한다. **내보내기**는 현재 결과를 검증한 뒤 별도 폴더에 사업 파일과 확정 사람 파일을 함께 저장한다. 계획 작업 파일과 다른 모드의 원본 경로에 덮어쓰지 않으며 실적 입력을 자동 변경하지 않는다.

계획 계산은 사업 상한과 각 사람의 월별 가용량을 함께 고려한다. 두 순위는 기본 가중치 `3:2`, 세 순위 이상은 `k:…:1`이며 동순위 사업은 가능한 비슷하게 배분한다. 참고값의 비율 자체를 사용하지 않으므로 `0.9/0.1`도 기본 희망 비중은 `3:2`다. 상한·기간·휴직 등의 제약은 우선순위보다 앞선다. 완전한 해가 없으면 부분 초안·미배정량·원인을 표시하고 확정 내보내기를 막는다. 2자리 후보를 우선 시도하되 필요하면 5자리 값을 쓰며 모든 2자리 해를 탐색하지는 않는다.

계획 저장은 `projects.yaml`과 `plans/plan_<연도>.yaml`에 입력 `draft`·선택적 `priorities`·현재 결과 `allocations`를 보존한다. 확정 내보내기는 별도 폴더의 `projects.yaml`과 `people/people_<연도>.yaml`에 쓰며 확정 사람 파일에는 `stage: confirmed`와 `allocations`를 사용한다. `stage` 없는 기존 실적 파일도 읽는다. 이전 계획의 `priorities`·`draft_allocations` 형식은 참고 점수 0·기존 순위 유지·결과를 `allocations`로 옮기는 방식으로 변환하고 안내한다. [이전 구현에서 변경한 내용](docs/annual-planning.md#이전-구현에서-변경한-내용)을 참고한다.

**사업 입력** 탭은 좌우 두 표로 나뉜다. 두 표는 같은 사업이 같은 줄에 오고, 세로 스크롤과 현재 행(옅은 파란 띠)이 함께 움직인다.
- 좌측 `총 배정`은 그 사업의 모든 연도 배정인력 합계다. 보이지 않는 연도까지 더하며 편집할 수 없다. 형식이 틀린 값이 있으면 `?`로 표시한다.
- 우측 연도 열은 연속한 6개이며 2020~2050년 안에서만 스크롤된다. 처음에는 배정 항목이 있는 연도를 최대한 모두 보여 주고, 그 조건 안에서 관리 연도를 가운데에 가장 가깝게 둔다(짝수 열의 가운데 두 자리 중 오른쪽을 우선). 고른 연도가 이 범위 안에 있으면 해당 연도가 보이도록 창을 옮긴다. 배정 연도가 6년을 넘게 퍼지면 값이 있는 연도 수가 가장 많은 범위를 고른다. 스크롤바 양끝 화살표는 항상 보이며 한 해씩 이동한다. 보기 범위 밖의 배정 연도는 삭제하지 않고 합계·스크롤바 안내에 남긴다. 관리 연도 머리글은 굵게 표시한다. 맨 오른쪽 제외월 열은 연도 열보다 넓다.
- 칸에 배정인력을 입력하면 그 연도 항목이 생기고, 비우면 지워진다.
- 맨 오른쪽 `YYYY 제외월` 열은 현재 칸이 있는 연도를 따라 제목과 내용이 바뀐다. 제외할 월을 `3,4,5`처럼 입력한다. 그 연도에 배정인력이 없는 사업은 입력할 수 없지만 칸 배경은 일반 칸과 같다.
- 칸 색: 회색은 사업 기간 밖 연도(계산하면 경고), 연보라는 제외 월이 있는 연도, 붉은색은 입력 확인 필요. 마우스를 올리면 내용을 보여 준다.
- 엑셀에서 복사한 사업 × 연도 범위를 Ctrl+V로 한 번에 붙여 넣을 수 있다.

**사람 입력** 탭은 사람별로 입력한다.
- 왼쪽 목록에서 [사람 추가]로 사람을 더하고(`새 사람`, `새 사람 2`…로 추가되며 바로 이름을 고칠 수 있다), 이름을 두 번 눌러 바꾼다. 비어 있거나 다른 사람과 같은 이름은 받지 않고 원래 이름으로 돌린다. 합계가 맞지 않거나 입력을 확인해야 하는 사람은 목록에서 붉게 보인다.
- 사람을 고르면 오른쪽 표에 그 사람의 참여 사업(사업·참여율·사업명)이 나온다. [행 추가]로 행을 더하면 사업 드롭다운이 열린다. 드롭다운에는 관리 연도에 배정이 있고 사업 기간이 그 해와 겹치는 사업 중 이 사람이 아직 고르지 않은 사업이 잔여 배정과 함께 나온다(예: `AI품질 — AI 기반 품질 예측 플랫폼 구축 (잔여 0.41000)`). [행 삭제]로 그 사업을 뺀다.
- 표 아래에 사업 합계·공백·합계가 나오고, 합계가 1.00000이 아니면 붉은 안내가 붙는다. 그 아래에서 공백 기간을 입력한다.
- 엑셀에서 (사업, 참여율) 두 열을 복사해 붙여 넣을 수 있다. `사업명` 열은 자동으로 채워진다.

결과 화면 맨 위에는 관리 연도, `ERROR`/`WARNING` 건수, 계산 시각, 입력 파일 이름과 **엑셀 저장** 버튼이 있다. 결과 화면을 열 때마다 현재 입력으로 다시 계산하므로 별도 생성 버튼이 없다.

- 입력 표에서는 형식이 틀린 칸(날짜, 소수 5자리 초과, 약칭 공백·중복 등)을 붉게 표시하고 마우스를 올리면 고칠 방법을 보여 준다. 합계가 1.00000이 아닌 사람은 합계 칸이 붉다. 최종 판정은 결과 화면 검증 탭의 결과다.
- 입력 표는 엑셀에서 복사한 범위를 Ctrl+V로 현재 칸부터 붙여 넣고, Delete로 선택 칸을 지운다. 사업 약칭을 바꾸면 사람 참여율도 새 약칭으로 옮겨지고, 참여율이 있는 사업을 지울 때는 확인을 받는다. 사업 목록에 없는 약칭의 참여율은 지우지 않고 사람 입력 표에서 붉게, 종합 탭에서 `(미등록)` 열로 보여 준다.
- 저장하지 않은 입력이 있으면 입력 탭·연도 목록에 `*`가 붙고, 연도를 닫거나 새로 만들거나 창을 닫을 때 저장 여부를 확인한다. 계획에서는 오류 상태도 중간 저장할 수 있다.
- **내보내면 파일을 새로 쓰므로 원래 파일의 주석(`#`)과 서식은 남지 않는다.** 대신 이번 실행에서 처음 덮어쓸 때 원본을 같은 폴더에 `파일이름.bak`(예: `projects.yaml.bak`)으로 백업한다. 표 편집기에서 다루지 않는 항목(알 수 없는 필드, 중복 키)은 열 때 알려 주며 내보내면 빠진다.
- 사람 입력의 연도 칸 타이핑은 계산·내보내기 때 확정된다. 이미 열린 연도나 잘못된 연도면 진행하지 않고 알린다.
- 결과 그리드에서 셀을 골라 Ctrl+C를 누르면 탭으로 구분한 값이 복사되어 엑셀에 바로 붙일 수 있다.
- **결과 → 개인상세**에서 사업명 셀을 위·아래로 드래그하면 사업 행 전체가 이동한다. `공백`·`합계` 행은 마지막 두 행에 고정한다. **결과 → 사업상세**에서는 사람 이름 셀을 드래그해 사람 행 전체를 이동하며, `합계` 행은 마지막에 고정한다.
- **실적 입력 → 종합**에서 사람 이름 셀을 드래그하면 사람 행, 사업 머리글을 좌·우로 드래그하면 사업 열 전체가 이동한다. 이름 열은 맨 앞, `할당합계`·`공백`·`합계` 열은 맨 뒤에 고정되어 이동하거나 넘어갈 수 없다. 맨 아래 `사업별합계` 행은 고정 행이며 드래그로 이동하지 않고 두 번 눌러도 사람 입력으로 가지 않는다. 사람 행을 두 번 누르면 이동한 표시 순서와 관계없이 해당 사람의 입력으로 간다.
- Ctrl+C는 드래그로 바꾼 **화면의 행·열 순서대로** 복사한다. 순서는 현재 실행 중 표를 새로 고치거나 사람·사업을 바꿨다가 돌아와도 기억한다. 표시 순서 변경은 입력 수정으로 기록되지 않으며, YAML이나 계산값·엑셀 저장 파일의 순서를 바꾸지 않는다. 프로그램을 다시 시작하면 기본 순서다.

- **엑셀 저장**은 CLI의 `--excel`과 같은 파일을 만든다.
- `ERROR`가 있으면 검증 탭만 보여 주고 엑셀 저장을 막는다.
- 모드별 불러온 파일 목록·선택 연도는 다음 실행 때 각각 복원한다.
- 글자 크기는 기본 10pt이며 **보기** 메뉴 또는 Ctrl + `+`(Ctrl + `=`) / Ctrl + `-`로 7~24pt 사이에서 조절하고 Ctrl + `0`으로 기본값으로 돌린다. 바꾼 크기는 다음 실행 때도 유지된다.
- CLI는 작업 디렉터리의 `projects.yaml`을 읽지만, GUI는 사업 파일 경로를 직접 고른다.

Linux에서는 Qt 실행에 필요한 시스템 라이브러리(예: Debian/Ubuntu의 `libxkbcommon-x11-0`, `libxcb-cursor0`, `libegl1`)가 있어야 한다.

### Windows 단일 실행파일

배포용 실행파일은 필요할 때 수동으로 빌드한다. 소스 수정만으로 `publish/win/Prouman.exe`가 자동 갱신되지는 않는다. Windows x64 빌드 환경에서 GUI 실행파일을 만들려면 PowerShell에서 다음을 실행한다.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\build_win.ps1
```

결과는 `publish/win/Prouman.exe` 한 파일이다. 대상 PC에는 Python·PySide6를 따로 설치할 필요가 없다. 실행파일을 열어 **불러오기**에서 기존 `projects.yaml`·확정 사람 파일 또는 계획 파일을 선택한다. 업무용 YAML은 실행파일에 들어 있지 않으며, `publish/win`에는 실행파일만 생성한다. 빌드 임시 파일은 `build/pyinstaller`에 놓는다. 빌드는 PyInstaller 6.22.3과 `requirements-gui.txt`의 패키지를 사용하며, 출력은 Git에서 제외한다.

인터넷이 없는 빌드 PC에서는 같은 Python·Windows x64 환경에서 미리 wheel을 준비한다. 빌드 도구의 하위 의존성도 필요하므로 `--no-deps`를 쓰지 않는다.

```powershell
python -m pip download --only-binary=:all: -r requirements-build.txt -d .wheels
.\.venv\Scripts\python.exe -m pip install --no-index --find-links=.wheels -r requirements-build.txt
.\build_win.ps1
```

2026-11-09 사용자 요청으로 YAML 인코딩 선택·원본 인코딩 유지와 최신 GUI 변경을 포함한 `publish/win/Prouman.exe`를 다시 빌드했다. Windows 11 x64의 저장소 밖 작업 폴더에서 12초간 실행 유지·응답 상태·새 UI 창 제목을 확인했다. 소스 기반 Windows Qt 인코딩 테스트 20개와 전체 회귀 189개(183개 통과·Linux용 6개 건너뜀), 실행파일 자체의 시작 점검은 구분한다. 실행파일에서 모든 파일 대화상자·저장 흐름을 클릭하거나 Python 없는 다른 Windows PC에서 실행하는 검증은 남아 있다. 파일 크기·해시·실행한 검증은 `SESSION.md`의 최신 빌드 항목을 따른다.

- `src/allocation/rendering.py`: 진단·요약·상세표 출력과 공용 집계

- `src/allocation/planning.py`, `src/allocation/planning_gui.py`: 연간 초안 계산·검증과 별도 계획 화면

## 테스트

```bash
.venv/bin/python -m unittest discover -s tests -v
```

표준 라이브러리 `unittest`를 사용한다. 모든 성공 fixture는 반복 실행과 YAML 항목 순서 변경 결과를 비교한다. 작은 정수 흐름 문제 200개는 완전 탐색과 비교하며, 외부 소켓을 금지한 상태에서 CLI도 검증한다. 테스트는 임시 YAML을 사용하고 예제 파일을 수정하지 않는다. GUI 테스트는 창을 띄우지 않는 `offscreen` 플랫폼에서 실행하며 사용자 설정(QSettings) 대신 임시 설정 파일을 쓴다.

Linux용 Bash 스크립트 테스트(`venv.sh`, `run_gui.sh`)는 Windows에서 건너뛴다. PowerShell 스크립트 테스트는 `pwsh` 또는 `powershell`이 있는 환경에서 실행하며 자식 프로세스 출력을 UTF-8로 읽는다.
