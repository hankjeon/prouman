# 기능 요구사항 및 수용 기준

## 업무 구분과 구현 상태

**실적작업**은 확정된 사람별·사업별 연간 할당량을 월별로 나누는 기존 기능이다. **계획작업**은 해당 연도 사업 배정인력·기간 등의 조건 안에서 연간 할당량을 정하는 독립 업무다. 실행 시점은 제한하지 않는다. 용어·절차의 기준은 [업무 명세](annual-planning.md)다.

2026-11-07 합의를 **소스에 구현**했다. 아래 R01~R19 및 월별 결과 규칙은 실적작업에 적용하며, 계획작업 요구사항은 RP01~RP10으로 분리한다. 모드별 독립 자료·입력/결과 탭과 새 계획 형식을 사용한다. 실적 월별 알고리즘은 유지하며 실제 검증 결과와 남은 경계는 `SESSION.md`를 따른다.

## 기준 인력과 집계

각 분기 기준은 `0.25000`이다. 매 분기 첫 두 달은 `0.08333`, 마지막 달(3·6·9·12월)은 `0.08334`다. 따라서 12개월 합계는 `1.00000`이다. 월별 사업 할당 + 월별 공백은 해당 월 기준과 **정확히** 같아야 한다. 분기별 내부 검증과 연간 집계는 월별 결과를 합산한다. 출력 표에는 1~12월과 연간만 표시한다.

입력 연간 목표의 합은 공백 인력의 연간 합계와 함께 정확히 `1.00000`이어야 한다. 휴직이 없으면 사업별 연간 목표 합계가 `1.00000`이어야 한다. 휴직이 있으면 `1.00000 - 연간 공백 인력`이어야 한다. 남거나 넘치는 인력을 자동으로 새 사업에 배정하거나 기존 사업 목표를 바꾸지 않는다.

## 결과 및 실패 동작

기본 출력은 입력 파일·관리 연도, 검증 `ERROR`/`WARNING` 건수, 개인별·사업별 연간 요약이다. `--person`은 특정 인물의 사업별 1~12월 상세와 공백·월 합계, `--project`는 해당 사업에 연간 양수 할당이 있는 사람별 1~12월과 연간 할당, 사업의 월별·연간 할당 합계와 연간 배정/할당/잔여, `--all`은 전체 개인별·사업별 상세를 출력한다. `--all-people`은 전체 개인 상세만, `--all-projects`는 전체 사업 상세만 출력하며 두 옵션 모두 전체 연간 요약은 생략한다. `--person`·`--project`에서는 개인별·사업별 전체 연간 요약을 출력하지 않고 선택한 대상의 상세만 출력한다. 사업 상세에는 해당 사업의 연간 배정/할당/잔여를 포함한다. 입력 파일·관리 연도와 검증 결과는 모든 모드에서 표시한다. `--all`은 전체 요약, 전체 개인 상세, 전체 사업 상세를 순서대로 출력한다. 할당이 없는 사업도 사업 상세에 포함하며, 각 요약과 개인·사업 상세 앞에는 빈 줄과 구분선을 넣는다. 이름/별칭 미발견도 오류로 알린다. 모든 성공 출력은 5자리 고정 소수로 표시한다.

`--person`·`--all-people`·`--all`의 개인 상세에는 사업별·공백·합계의 1~12월 및 연간 집계를 포함한다. `--project`·`--all-projects`·`--all`의 사업 상세도 1~12월과 연간만 표시하며 분기별 열은 출력하지 않는다. `--person`·`--project`·`--all-people`·`--all-projects`·`--all`은 상호 배타적이며 동시에 지정하면 오류다. 기본 사업 파일은 실행 작업 디렉터리의 `projects.yaml`이다. 사업명·사업약칭의 공백 처리와 참조 기준은 [data-model.md](data-model.md)를 따른다.

`--excel PATH.xlsx`는 조회 옵션과 함께 쓸 수 있으며, 화면 출력은 조회 옵션을 따르고 엑셀 파일에는 조회 옵션과 관계없이 전체 결과를 저장한다. 시트는 `검증`(관리 연도·입력 파일·검증 건수·이슈 목록), `요약`(개인별·사업별 연간 요약), `개인상세`(사람별 사업·공백·합계의 1~12월·연간 표), `사업상세`(사업별 배정·할당·잔여와 1~12월 할당) 순서다. 수량은 숫자 셀에 정확한 십진 값으로 기록하고 표시 형식은 `0.00000`이다. 합계는 엑셀 수식이 아니라 계산된 값이다. `ERROR`가 있으면 파일을 만들지 않고 종료 코드 1, `WARNING`만 있으면 파일을 만들고 경고를 `검증` 시트에 넣는다. 같은 경로의 파일은 덮어쓴다. 같은 폴더의 임시 파일에 다 쓴 뒤 바꿔 넣어, 저장에 실패하면 기존 파일을 그대로 두고 임시 파일을 지운다. 확장자가 `.xlsx`가 아니면 사용법 오류(종료 코드 2), 저장 실패(파일이 열려 있음 등)는 종료 코드 1이다. 엑셀이 파일을 열 때 숫자 셀을 배정밀도로 읽으므로, 엑셀 안에서 다시 계산한 값은 5자리 고정 소수 결과와 미세하게 다를 수 있다. 기준 값은 텍스트·셀에 기록된 값이다.

GUI 상단에서 실적작업·계획작업 모드를 선택한다. 각 모드의 **입력·결과 탭**은 Ctrl+1·Ctrl+2와 `보기` 메뉴로도 바꾼다. 모드별 사업·사람 자료·연도·결과·수정 상태를 따로 유지한다. 실적 입력은 불러오기·저장/내보내기·새로 만들기·연도 목록 및 `사업 입력`·`사람 입력`·`종합`으로 구성한다. 실적 결과는 계산 정보·엑셀 저장 및 `검증`·`요약`·`개인상세`·`사업상세`로 구성한다. 실적 결과 탭으로 가면 현재 입력을 바로 계산한다(성공: 요약, `ERROR`: 검증과 입력 수정 안내). 머리 줄에는 관리 연도, `ERROR`/`WARNING` 건수, 계산 시각, 사업·사람 파일 이름(합친 파일은 쉼표로 잇고 없으면 새 입력 표시)을 보인다. 계획 결과는 별도 계산 명령으로 생성하며 탭 진입만으로 수동 결과를 덮어쓰지 않는다. 파일·엑셀 처리 메시지는 해당 모드의 상태 표시줄에 보인다.

GUI의 상단 `파일` 메뉴는 `새로 만들기` → `불러오기` → `저장` → `내보내기` → `종료` 순서다. Ctrl+S는 저장, Ctrl+Shift+S는 내보내기이며 선택 모드에 따라 처리한다. 계획 저장은 작업 자료 보존, 계획 내보내기는 검증된 현재 결과의 확정이다. 종료는 두 모드의 미저장 변경을 모두 확인한다. 연도 추가는 해당 모드의 연도 행에서 수행한다.

GUI의 **불러오기**는 사업·사람 파일을 구분 없이 여러 개 받으며, 최상위 키(`projects`/`people`)로 종류를 판별한다. 둘 다 아니거나 문법·구조가 맞지 않는 파일은 사유와 함께 건너뛴다. 사람 파일은 같은 연도끼리 합치고 다른 연도는 별도 문서로 두며, 같은 연도에 같은 이름이 있거나 이미 열린 사업 약칭과 겹치면 그 파일 전체를 열지 않고 알린다. 빈 문서에 넣으면 채우기로 보고 깨끗하게 두고, 내용이 있는 곳에 덧붙이면 합치기로 보고 내보내기 표시를 한다. 사람 파일을 불러올 때 사업 입력이 비어 있고 깨끗하면 사람 파일 폴더와 바로 위 폴더 순서로 `projects.yaml`을 찾아 함께 연다.

GUI의 `사업 입력` 탭은 좌우 두 표로 나뉜다. 좌측 사업 목록은 사업명·약칭·시작일·종료일과 계산 칸 `총 배정`(그 사업의 모든 연도 배정인력 합계, 형식 오류가 있으면 `?`)을 보인다. 우측 사업 × 연도 표는 연속한 6개 연도(처음에는 유효한 연도 키의 배정 항목을 가장 많이 포함하는 범위를 고르고, 동률이면 관리 연도가 가운데에 가장 가까운 범위를 고름; 짝수 열의 중앙 두 자리가 동률이면 오른쪽 자리를 우선함; 배정 연도가 없으면 관리 연도가 오른쪽 중앙 자리에 오게 하고, 관리 연도가 없거나 잘못되면 올해를 사용함; 연도를 바꾸거나 새로 만들 때 이 범위로 돌아감)의 배정인력과, 맨 오른쪽에 고정된 `YYYY 제외월` 열을 보인다. 두 표는 같은 행이 같은 사업이고, 행·머리글 높이, 세로 스크롤, 현재 행이 맞물린다. 표 아래 가로 스크롤바로 연도 창을 옮긴다. 스크롤 범위는 2020~2050년이며 6년 창의 첫 연도는 2020~2045로 제한한다. 고른 관리 연도가 이 범위 안에 있으면 그 연도가 창에 보이도록 옮긴다. 기본 스크롤바의 양끝 화살표를 항상 보여 한 해씩 이동하되 양 끝에서 멈춘다. 범위 밖의 배정 연도는 삭제하지 않고 합계와 스크롤바 안내에 남긴다. 보이지 않는 배정 연도는 스크롤바 툴팁에 나열한다. 연도 열은 등간격이고 제외월 열은 연도 열보다 넓다. 연도 칸에 값을 입력하면 해당 연도 배정 항목을 만들거나 고치고, 비우면 제외 월이 없을 때만 항목을 지운다. 제외 월이 남아 있으면 빈 배정으로 남겨 오류로 표시한다. `YYYY 제외월` 열은 현재 칸이 있는 연도를 따르고, 그 연도에 배정 항목이 없는 사업은 입력할 수 없지만 제외월 칸 배경은 일반 칸과 같다. 칸 배경은 입력 오류(붉은색), 제외 월 있음(연보라), 사업 기간 밖 연도(회색, 계산하면 W002 경고) 순서로 우선한다. 연도 키가 4자리 연도가 아니거나 중복된 항목은 표에 나타내지 않고 건수만 알리며 값은 그대로 두어 계산 검증으로 넘긴다. `사람 입력` 탭은 관리 연도와 사람별 입력을 편집한다. 왼쪽 사람 목록에서 사람을 추가·삭제하고 이름을 바꾸며, 이름은 비어 있거나 다른 사람과 같을 수 없다(그런 이름은 받지 않고 원래 이름으로 돌린다). 새 사람은 `새 사람`, `새 사람 2`…처럼 겹치지 않는 이름으로 추가한다. 고른 사람의 참여 사업 표(사업·참여율·사업명)는 행 추가·삭제로 사업을 더하거나 뺀다. 사업 칸은 드롭다운으로 고르며, 목록에는 관리 연도에 배정 항목이 있고 사업 기간이 그 해와 겹치는 사업 중 그 사람이 다른 행에서 고르지 않은 사업을 잔여 배정(배정 − 전체 사람의 참여율 합계)과 함께 보인다. 한 사람에게 같은 사업을 두 번 넣을 수 없다. 표 아래에 사업 합계·공백·합계를 보이고, 그 아래 휴직 기간(시작일·종료일·사유)을 편집한다. 합계가 1이 아니거나 입력 확인이 필요한 사람은 목록에서 붉게 표시한다. `종합` 탭은 사람 × 사업 참여율 전체 표를 읽기 전용으로 보이며, 행을 두 번 누르면 그 사람의 입력 화면으로 간다. 편집기는 입력한 문자열을 그대로 보관하고, 계산·내보내기 때 YAML로 만든다. **계산은 내보내기 전 현재 입력 내용**을 파일과 같은 `load_inputs` 검증(위치 표시는 파일 이름, 합친 파일은 쉼표로 잇고 없으면 `(새 사업 입력)`·`(새 2027 입력)`)과 계산에 넘긴다. 편집기는 계산·검증 규칙을 따로 두지 않으며, 입력 중에는 형식 오류 칸(날짜, 수량 형식, 연도·제외 월, 사업명·약칭 누락, 약칭 공백·중복, 사람 이름 누락·중복, 사업 목록에 없는 약칭)과 사업 합계 + 공백 ≠ `1.00000`인 사람의 합계 칸만 안내한다. 공백은 계산 엔진과 같은 월별 반올림으로 구한다. 사업 약칭을 바꾸면 그 약칭이 이 사업에만 쓰였고 새 약칭이 다른 사업과 겹치지 않을 때 사람 참여율 키도 바꾼다. 참여율이 있는 사업을 지우면 확인을 받고 해당 참여율도 지운다. 사업 목록에 없는 약칭의 참여율은 지우지 않고 사람 입력 표에서 붉게, 종합 탭에서 `(미등록)` 열로 보인다. 사업을 고르지 않은 행(빈 약칭)과 빈 참여율도 붉게 안내하며, 빈 참여율 행은 내보내지 않는다.

실적작업의 **저장·내보내기**는 폴더를 받아 `projects.yaml`과 연도별 `people/people_<연도>.yaml`을 쓴다(`people/`은 없으면 만든다). 문서 모델에서 YAML을 새로 쓰므로 원래 파일의 주석과 서식을 유지하지 않는다. 이름·약칭·기간·수량은 큰따옴표 문자열, 연도와 제외 월은 정수로 쓰며(숫자가 아니면 문자열로 써서 같은 검증 오류를 받는다), 빈 참여율 칸은 쓰지 않는다. 같은 실행에서 기존 파일을 처음 덮어쓰기 전에 원본을 `파일이름.bak`으로 복사한다. 파일을 열 때 편집기가 다루지 않는 필드는 목록을 알려 주고, 내보내면 빠진다. 문법 오류·구조 불일치·중복 항목은 안내한다. 미저장 변경은 입력 탭·연도 목록의 `*`로 표시하고, 연도를 닫거나 새로 만들거나 창을 닫을 때 저장·버리기·취소를 묻는다. 편집기 형식으로 읽고 다시 쓴 정상 파일은 원본과 같은 입력·결과·진단을 만들어야 한다(T30). 계획 저장·내보내기는 RP09·RP10 및 업무 명세의 보존·검증 규칙을 따르며 알 수 없는 계획 필드·중복 키를 조용히 버리지 않는다.

계산 결과는 `검증`·`요약`(개인별·사업별 연간 요약)·`개인상세`(사람 목록에서 고른 사람의 사업·공백·합계 1~12월·연간 표)·`사업상세` 탭에 표시한다. `사업상세` 탭은 왼쪽 사업 목록에서 사업을 고르면 오른쪽에 배정·할당·잔여와 양수 할당 참여자별 1~12월·연간 할당 및 합계를 표시한다. 0 할당자는 제외하며 참여자가 없는 사업은 0 합계만 표시한다. GUI 이외 엑셀 사업상세는 기존 표를 유지한다. 수량은 5자리 고정 소수 문자열로 오른쪽 정렬한다. 로드 실패나 `ERROR`가 있으면 검증 탭만 채우고 결과 탭을 비우며 엑셀 저장을 막는다. `WARNING`만 있으면 결과를 표시한다. 엑셀 저장은 `--excel`과 같은 파일을 만들고, 저장 실패는 경고 대화상자로 알린다. 그리드에서 선택한 셀은 포커스와 관계없이 같은 배경색으로, 현재 셀은 테두리로 표시하고, Ctrl+C로 탭 구분 텍스트(표시 문자열 그대로, 선택하지 않은 칸은 빈 칸)로 복사한다. 불러온 파일 목록과 고른 연도는 사용자 설정(QSettings)에 저장해 다음 실행 때 다시 연다. 글자 크기는 기본 10pt이며 `보기` 메뉴와 Ctrl + `+`·`=`/`-`/`0` 단축키로 7~24pt 사이에서 바꾸고, 행 높이·열 너비를 새 크기에 맞춘다. 사용자가 바꾼 크기만 사용자 설정에 저장한다.

가능한 검증 오류를 한 번에 모아 출력하되, 의미 없는 후속 검증은 건너뛴다. `ERROR`가 하나라도 있으면 최종 할당표를 생성하지 않고 종료 코드 0이 아닌 값으로 끝낸다. `WARNING`만 있으면 계산을 계속하며 종료 코드는 0이다. 출력용 통계는 해에서 다시 집계한다.

## 오프라인 의존성 준비

실행 시 외부 통신을 요구하지 않는다. 외부 패키지를 도입하면 버전을 고정하고, 인터넷이 가능한 환경에서 wheel을 준비한 뒤 오프라인 환경에서 해당 파일만으로 설치하는 절차를 제공한다. 오프라인 설치와 실행은 각각 검증한다.

## 계획작업 재정의 요구사항

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| RP01 | 독립 작업 모드 | 상단 메뉴·툴바에서 실적작업·계획작업 선택, 모드별 입력·결과 탭. 전환으로 자료를 변환·확정·덮어쓰지 않고 편집 상태 유지. |
| RP02 | 사업 기록과 계획 연도 배정 | 종료 사업은 기록 보존·해당 연도 후보 제외. 계획 연도 수행 사업은 참여 여부와 무관하게 해당 연도 배정인력이 필수. 누락과 명시적 0 구분. 실적의 기존 누락 판정은 변경하지 않음. |
| RP03 | 직전 자료 활용 | 실적 파일 사본의 연도·단계 변경과 `allocations` → `draft`로 새 계획 준비 가능. 사람·사업 추가·삭제 및 휴직 확인. 휴직 날짜 자동 이동 없음. 새 작성도 허용. |
| RP04 | 참고값 기반 순위 | `draft`의 키는 참여 사업이며 0도 참여 대상. 값의 크기로만 순위를 정하고 합계 1이나 원래 값 비율을 강제하지 않음. 모두 0이면 동순위. |
| RP05 | 선택적 명시 순위 | `priorities`가 있으면 참고값 크기를 무시. 미기재 참여 사업은 명시 최하위보다 한 단계 아래 동순위. `draft`에 없는 사업의 순위는 오류. |
| RP06 | 순위 가중치와 균형 | 두 단계 `3:2`, 세 단계 이상 `k:…:1`, 동순위 각 사업은 같은 초기 가중치. 전체 사람·사업을 고려해 비슷한 비중을 노력하되 사업 상한은 절대 초과하지 않음. |
| RP07 | 기존 계획 필수 조건 유지 | 개인 총량·휴직·선택 사업 최소 `0.01000`, 2자리 우선·필요 시 5자리, 월별 실행 가능성 검증 유지. 기존 실적 월별 알고리즘은 변경하지 않음. |
| RP08 | 참고값과 결과 분리 | 입력 `draft`·선택적 `priorities`, 계산·수정 결과 `allocations`. 계산은 참고값을 덮어쓰지 않으며 수동 결과 재생성 전 확인. 결과 탭 진입만으로 덮어쓰지 않음. |
| RP09 | 계획 중간 저장 | 미완성·오류 상태도 사업 자료와 계획 파일에 보존·재개. 저장이 확정이나 검증 통과를 뜻하지 않음. |
| RP10 | 확정 내보내기 | 현재 결과와 조건을 재검증하고 별도 폴더에 `projects.yaml`·`people/people_<연도>.yaml` 묶음 저장. 확정 파일에는 `stage: confirmed`·`allocations`, 계획 참고값·순위는 제외. 오류 차단·경고 허용. |

RP01~RP10은 [수용 사례 NP01~NP17](test-cases.md#계획작업-재정의의-수용-사례)과 `tests/test_workflows.py`로 검증한다. 이전 계획은 참고 점수 0·기존 순위·결과 보존으로 변환하고, 빈 `priorities`는 점수 방식을 쓴다. 모드별 사업 문서는 독립적이며 계획 묶음 저장은 준비 후 교체·실패 복구를 수행한다. [구현 결정과 검증 경계](annual-planning.md#구현-세부-결정과-남은-검증-경계)를 참고한다.

## 호환과 후속 범위

이전 계획의 필수 `priorities`·결과 `draft_allocations`는 호환 변환하여 읽고 새 형식으로 저장한다. 계획 파일은 실적 CLI 입력이 아니며 실적 엔진은 확정 연간 목표를 변경하지 않는다. Windows 단일 GUI 실행파일은 명시적 요청이 있을 때 `build_win.ps1`으로 `publish/win`에 만든다. 그래프·CSV와 일반적인 월별 직접 입력은 후속 범위다. 실적 fixed의 12개월 고정 입력은 R19의 명시적 예외다.

## GUI 표의 드래그 표시 순서

결과 개인상세의 사업명 셀, 사업상세의 사람 이름 셀을 드래그해 행 전체를 이동한다. 개인상세의 공백·합계 행과 사업상세의 합계 행은 끝에 고정하고 이동할 수 없다. 실적 입력 종합에서는 사람 이름 셀로 행, 사업 머리글로 열을 이동한다. 이름 열과 끝의 사업 합계·공백·합계 열은 고정하며 사업 열이 그 영역을 넘지 못한다.

표의 논리 데이터와 계산은 바꾸지 않고 표시 순서만 바꾼다. Ctrl+C는 표시 순서로 선택 범위를 복사하고 선택하지 않은 칸은 빈칸으로 유지한다. 이동 후에도 사람·사업·수치의 대응과 종합의 두 번 클릭 대상은 정확해야 한다. 현재 실행 중 사람/사업별 표와 연도별 종합의 순서를 기억하고 새 행·열을 추가하면 기존 순서를 유지한 뒤 새 항목을 붙인다. 사라진 항목은 제외하며 고정 영역은 유지한다. 재시작 저장, YAML 항목 순서 변경, 엑셀 저장 파일의 순서 변경은 포함하지 않는다.

실적 사람 입력에는 월별 고정 표가 있다. 참여 사업을 고른 뒤 [선택 사업 월 고정]으로 12개 0인 고정값을 만들고 직접 입력할 수 있다. 월 고정 표는 12개월 수량 붙여넣기도 지원한다. 고정 해제는 [선택 고정 해제]로 명시적으로 수행한다. 고정된 사업의 참여율 행을 삭제하거나 다른 사업으로 바꾸려면 먼저 해제한다. 사업 입력에서 동일 사업의 약칭을 바꾸면 고정 참조도 옮기며, 새 약칭에 기존 고정값이 있으면 덮어쓰지 않고 원본을 남겨 검증으로 알린다. 사업 자체를 확인 후 삭제하면 해당 연도들의 고정 참조도 삭제한다. 구조 오류를 가져올 때 기존 문서·화면을 유지하고, 수량/합계 오류 후에도 입력/결과 탭을 오가며 고칠 수 있어야 한다.
