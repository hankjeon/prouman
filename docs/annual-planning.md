# 계획작업·실적작업 정의와 사용 절차

> 기준: **2026-11-07 사용자 합의 반영 구현**. 작업 모드별 입력·결과, 새 계획 형식, 참고 점수·선택적 순위, 중간 저장·별도 폴더 묶음 내보내기를 소스에 구현했다. 기존 실적작업의 월별 알고리즘은 변경하지 않았다. 실제 수행한 검증과 남은 경계, 사용자 요청에 따른 배포용 실행파일의 최신 빌드 상태는 [SESSION.md](../SESSION.md)의 최신 관련 항목을 따른다.

## 용어 정의

| 용어 | 정의 |
| --- | --- |
| 계획작업 | 신규·기존 사업과 신규·기존 사람을 대상으로, 해당 연도의 사업 배정인력·기간 등의 조건에 맞춰 사람별·사업별 연간 할당량을 정하는 작업. |
| 실적작업 | 연초 계획과 연중 수정 등을 거쳐 이미 결정된 사람별·사업별 연간 할당량을 가능하면 균등하게 월별로 나누는 작업. 계산 중 연간 할당량을 바꾸지 않는다. |
| 사업 배정인력 | 사업이 해당 연도에 배정받은 인력 수치. 전체 참여자의 연간 할당 합계에 대한 상한이다. |
| 연간 할당량 | 한 사람이 해당 사업에 할당받는 연간 인력 수치. 계획에서는 산정 대상이고 실적에서는 고정 입력이다. |
| 계획 참고값 (`draft`) | 참여 사업과 상대적인 우선순위를 나타내는 입력 점수. 직전 할당값을 가져오거나 직접 입력하며, 확정 할당량이 아니다. |
| 명시적 우선순위 (`priorities`) | 선택적인 순위 입력. 작은 양의 정수일수록 높은 순위이며, 있으면 `draft` 값의 크기보다 우선한다. |
| 계획 결과 (`allocations`) | 계산 또는 직접 수정한 현재 연간 할당안. 계획 파일에서는 미완성·오류 상태일 수도 있다. |
| 확정값 | 개인 총량·사업 상한·최소 참여·월별 실행 가능성 등의 검증을 통과하여 내보내는 현재 계획 결과. |
| 공백 인력 | 휴직 등으로 사업에 할당할 수 없는 인력. 기존 월별 달력 계산을 따른다. |

- ‘실적’은 실제 월별 근무 시간 기록을 입력한다는 뜻이 아니라 **결정된 연간 할당량을 월별로 나누는 업무의 명칭**이다.
- 계획을 주로 연초에, 실적을 주로 연말에 수행하더라도 프로그램의 실행 시점 제약은 아니다. 관리 연도는 파일 안의 `year`로 결정한다.
- 사업 배정인력은 금액이 아니다. 배정 상한을 전부 소진할 필요는 없으며 잔여가 있어도 정상이다.

## 두 작업의 관계와 화면 구성

두 작업은 **독립된 업무**다. 현재 실적작업을 마친 뒤 다음 연도 계획작업을 하고, 나중에 다시 실적작업을 하는 식으로 반복할 수 있다.

- 실적작업 전에 프로그램의 계획작업을 반드시 실행할 필요는 없다. 외부에서 이미 정한 연간 할당 파일도 실적 입력으로 사용할 수 있다.
- 계획작업은 직전 실적 자료에서 시작하거나 완전히 새로 작성할 수 있다.
- 계획의 월별 실행 가능성 검사는 잘못된 연간 목표를 방지하기 위한 것이다. 두 업무를 하나의 필수 연속 단계로 묶는다는 뜻이 아니다.
- 계획 결과를 실적 입력으로 쓸 때는 별도 폴더로 내보내고 명시적으로 불러온다. 모드 전환만으로 변환·확정·덮어쓰지 않는다.

UI는 메뉴바 우측 끝의 작업모드 콤보 상자와 `작업` 메뉴에서 모드를 선택하고, 각 모드 안에 입력·결과 탭을 두는 구조다. 기존 좌측 `입력 / 결과 / 계획` 세 선택을 대체했다.

```text
작업 모드: [ 실적작업 ] [ 계획작업 ]

선택한 모드의 탭: [ 입력 ] [ 결과 ]
```

| 모드 | 입력 | 결과 |
| --- | --- | --- |
| 실적작업 | 사업 조건, 확정 연간 할당량, 휴직 등 | 기존 엔진의 월별 할당표, 검증·요약·개인상세·사업상세 |
| 계획작업 | 사업 배정인력·조건, 참여 사람·사업, 참고값·선택적 순위, 휴직 등 | 사람 × 사업 연간 할당안, 개인 합계, 사업 상한·잔여, 검증·수정 |

현재 모드는 메뉴바의 작업모드 콤보 상자와 창 제목에 표시한다. 모드별 사업·사람·선택 연도·입력·결과·수정 상태와 재시작 파일 목록을 따로 유지하며, 한 모드의 수정이 다른 작업 자료에 암묵적으로 반영되지 않는다. 각 모드에 필요한 사업 파일은 따로 불러온다. 입력·결과는 좌측 세로(서쪽) 탭으로 전환하며, 실적·계획 모드는 Ctrl+Alt+1·Ctrl+Alt+2로 전환한다.

## 사업 자료 준비와 기록 유지

1. 직전 실적작업의 `projects.yaml`을 출발점으로 삼거나 새로 작성한다. 원본을 보존하고 계획용 사본에서 변경하는 것이 안전하다.
2. 신규 사업을 추가하고, 계속되는 사업의 계획 연도 배정인력을 입력·조정한다.
3. 사업 기간과 해당 연도 제외 월을 정비한다. 사업 식별은 기존 `alias`를 사용하며 별도 YAML ID를 요구하지 않는다.
4. 종료된 사업도 과거 기록으로 유지하되 계획 연도 대상 목록에서는 제외한다. 목록에서 숨기는 것과 원본 정보를 삭제하는 것을 구분한다.

**사업 기간이 계획 연도와 하루라도 겹치면 해당 연도의 배정인력이 필수다.** 예를 들어 2027년 수행 사업에 `yearly.2027` 또는 그 안의 `allocated_manpower`가 없으면 계획 오류다. 사람의 참여 목록에 없는 사업도 검사한다.

- 누락과 명시적인 `0`은 다르다. `0`은 유효한 상한 정보다.
- 다만 상한 0인 사업에 참여를 요구하면 최소 참여 조건을 만족할 수 없으므로 유효한 계획으로 확정할 수 없다.
- 종료된 사업이 사람의 참여 목록에 남아 있으면 자동 삭제하지 않고 정비 필요를 안내한다. 불가능한 참여를 무시하여 정상 확정하지 않는다.
- 이 필수 배정 검사로 **실적작업의 기존 미등록 배정 경고·오류 규칙까지 바꾸지 않는다**.
- 사업 기간은 한 월과 하루라도 겹치면 월 전체를 허용하며 `excluded_months`의 월에는 할당하지 않는다. 날짜 범위 형태의 새 제외 기간 입력 기능을 추가하기로 한 것은 아니다.

## 파일 계약

### 실적작업용 사람 파일

```yaml
year: 2026
stage: confirmed
people:
  - name: 홍길동
    allocations:
      사업1: "0.60000"
      사업2: "0.40000"
```

`allocations`는 고정 연간 할당량이다. 기존처럼 `stage`가 없는 파일도 확정 입력으로 읽는다. 필요한 휴직은 선택적인 `absences`로 기록한다.

### 계획작업용 사람 파일

기본 위치는 `plans/plan_<연도>.yaml`이며 파일명보다 `year`가 우선한다.

```yaml
year: 2027
stage: planning
people:
  - name: 홍길동
    draft:
      사업1: "0.60000"
      사업2: "0.40000"
      신규사업: "0.80000"

  - name: 신입사원
    draft:
      사업1: "0.0"
      신규사업: "0.0"
```

- `draft`의 키가 참여 사업 목록이다. 참여하지 않게 된 사업은 항목 자체를 삭제한다.
- `0.0`도 참여 대상이다. 신규사업은 0이 아닌 값으로 추가하여 원하는 순위를 줄 수도 있다.
- 명시적 순위가 없으면 값이 클수록 높은 순위이고 같은 값은 동순위다. 전부 0이면 모두 동순위다.
- 값의 **대소관계만** 사용한다. 합계가 1일 필요가 없으며 배정 비율로 직접 사용하지 않는다. 예를 들어 `0.9 / 0.1`은 9:1이 아니라 두 순위의 기본 비중인 **3:2**로 시작한다.
- 기존의 비음수 십진 수·소수 5자리 이하·원문 Decimal 파싱 원칙을 유지한다. 점수에는 별도의 업무상 상한을 두지 않고 입력 문자열을 보존·표시한다. 개인 총량 제한을 참고값의 합계에 적용하지 않는다.

명시적인 순위를 쓰려면 같은 사람 아래에 선택적으로 추가한다.

```yaml
year: 2027
stage: planning
people:
  - name: 홍길동
    draft:
      사업1: "0.60000"
      사업2: "0.40000"
      신규사업: "0.80000"
    priorities:
      신규사업: 1
      사업1: 2
```

- `priorities`가 있으면 `draft` 값의 크기를 무시하고 명시적 순위를 사용한다.
- 순위는 불리언이 아닌 양의 정수이며 작은 숫자가 높다. 같은 순위를 허용한다. 숫자 사이의 빈 간격은 비중에 영향을 주지 않는다.
- 미기재 사업은 명시한 최하위보다 **한 단계 아래의 동순위**다. 위 예에서는 신규사업 → 사업1 → 사업2 순서다. 미기재 사업끼리 `draft` 값으로 순서를 다시 나누지 않는다.
- `priorities`에만 있고 `draft`에는 없는 사업은 오류다. 순위 입력으로 참여 목록을 자동 확장하지 않는다.
- `priorities: {}`는 생략과 동일하게 참고 점수의 대소관계를 사용한다. GUI에서 모든 명시 순위를 비우면 같은 동작이다. 순위 입력 범위는 기존과 같은 1~999999다.

### 중간 저장: 참고값과 결과 분리

```yaml
year: 2027
stage: planning
people:
  - name: 홍길동
    draft:
      사업1: "0.60000"
      사업2: "0.40000"
      신규사업: "0.80000"
    allocations:
      사업1: "0.33000"
      사업2: "0.17000"
      신규사업: "0.50000"
```

결과 수치는 형식 설명용 예시이며 실제 결과는 함께 입력한 사업 상한·기간·휴직 등으로 달라진다.

| 키 | 역할 |
| --- | --- |
| `draft` | 입력 참고값. 계산·결과 편집으로 덮어쓰지 않는다. |
| `priorities` | 선택적인 명시적 순위. 참고값의 대소관계보다 우선한다. |
| `allocations` | 계산하거나 직접 수정한 현재 결과. 미완성·오류 상태도 중간 저장한다. |

첫 계산 전에는 `allocations`를 생략하여 미계산과 결과 0을 구분한다. 결과 키는 기존과 같은 **복수형 `allocations`**이며 `allocation`이나 `draft_allocations`를 새 형식에 사용하지 않는다. 결과에만 있는 비선택 사업은 조용히 추가·삭제하지 않고 참여 목록과의 불일치를 안내한다.

## 계획작업 사용 절차

### 1. 새 연도 자료 준비

1. 계획작업 모드를 선택하고 사업 자료를 위 기준으로 정비한다.
2. 사람 자료를 새로 만들거나 직전 실적용 파일의 사본에서 시작한다.
3. 직전 파일을 쓴다면 `year`를 새 연도로 바꾸고 `stage: planning`으로 지정한다. 기존 `stage: confirmed`는 교체하며 중복 키를 만들지 않는다.
4. 각 사람의 기존 `allocations`를 `draft`로 바꾼다. 새 계획의 참고값이며 새 연도 확정값이 아니다. 계산 전 `allocations`는 남기지 않는다.
5. 없어진 참여 사업은 삭제하고 신규 참여 사업을 추가한다. 명시적 순위를 쓰는 사람은 `priorities`도 함께 정비한다.
6. 퇴직자는 `- name:`을 포함한 해당 사람 항목 전체를 삭제한다. 빈 사람 항목을 남기지 않는다.
7. 신입은 이름과 `draft`를 추가하고 참여 사업 값을 모두 0으로 두거나 원하는 점수를 넣는다.
8. 휴직 기간을 계획 연도에 맞게 확인한다. 연도 변경만으로 직전 휴직 날짜를 자동으로 1년 이동하지 않는다.

GUI에서는 계획 모드 입력 탭의 **실적 파일에서 계획 준비**를 선택해 실적 사람 파일과 새 계획 연도를 지정하면 위 참고값 변환을 수행한다. 원본 파일과 휴직 날짜는 바꾸지 않는다. 사업 자료는 계획 모드에서 별도로 불러와 새 연도 조건을 정비한다. 이미 같은 연도 계획이 있으면 교체 전 확인한다.

### 2. 계산·결과 수정·저장

1. 입력을 확인한 뒤 계획 계산을 실행한다.
2. 결과 탭의 사람 × 사업 연간 할당안, 개인 합계, 사업 상한·잔여, 검증 내용을 확인한다.
3. 입력 참고값·순위를 고쳐 재계산하거나 현재 결과를 직접 수정한다. 한 셀을 직접 바꿔도 다른 셀을 자동 조정하지 않는다.
4. 참고값·사업 조건·휴직 등을 바꾸면 이전 결과를 새 조건에서 검증된 결과로 간주하지 않는다. 현재 결과를 다시 검증하거나 재계산한다.
5. 재계산은 `draft`·`priorities`를 기준으로 하며 기존 결과를 새 참고값으로 자동 대체하지 않는다. 기존 결과가 있으면 덮어쓰기 확인을 받는다.
6. 필요할 때 저장한다. 미완성·오류 상태도 보존하고, 다시 열면 참고값·순위·휴직·현재 결과를 함께 복원한다.

계획 결과 탭을 열기만 해서 중간 저장한 수동 결과를 재계산·덮어쓰지 않는다. 사람 총량과 사업 상한 등의 문제는 합계·관련 셀·검증 목록에 표시하되 색만으로 의미를 전달하지 않는다.

### 3. 확정 내보내기

1. 최초 자동 계산값이 아니라 **현재 표의 값**을 최종 검증한다.
2. 오류가 있으면 원인을 안내하고 확정 내보내기를 막는다. 경고만 있으면 설명과 함께 허용한다.
3. 계획 작업 폴더와 구분되는 별도 폴더를 선택한다.
4. 그 계획에서 사용한 현재 사업 파일과 확정 사람 파일을 같은 검증 시점의 한 묶음으로 내보낸다.
5. 원래 계획 파일과 참고값·순위·현재 결과는 유지한다. 실적 모드로 자동 전환하거나 실적 입력을 자동 변경하지 않는다.

## 계획 계산·검증 기준

### 순위별 희망 비중

사람별 참여 사업의 서로 다른 순위 단계 수에 따라 다음 가중치를 부여한다. 같은 순위의 **각 사업**은 같은 가중치를 받는다.

| 서로 다른 순위 단계 수 | 높은 순위부터의 가중치 |
| --- | --- |
| 1 | 모두 같은 가중치 |
| 2 | `3 : 2` |
| 3 | `3 : 2 : 1` |
| 4 이상 | 단계 수 k에 대해 `k : k-1 : … : 1` |

초기 희망값은 `개인 연간 가용량 × 해당 사업 가중치 / 참여 사업 가중치 합`이다. 동순위 사업은 가능한 비슷하게 배분하되 정확히 같은 값을 강제하지 않는다. 사업 상한·허용 월 등으로 최종값이 희망값과 달라질 수 있다.

두 단계 `3:2`는 참여 사업 수가 정확히 두 개인 경우로 한정하지 않는다. 예를 들어 순위 `1, 1, 3`은 두 단계이므로 가중치 **`3, 3, 2`**다. 기존 구현의 `2, 2, 1`에서 변경하는 이유는 이번에 합의한 ‘두 순위는 3:2’를 일관되게 적용하기 위해서다.

### 필수 조건과 전체 균형

- 개인 연간 사업 합계 + 연간 공백 = 정확히 `1.00000`. 휴직이 없으면 사업 합계가 `1.00000`이다.
- 사업 전체 참여자의 연간 할당 합계는 해당 연도 배정인력을 절대 초과하지 않는다. 남은 배정인력은 허용한다.
- 선택한 각 사람·사업에는 기존 계획 규칙대로 연간 최소 **`0.01000`**을 배정한다. 조건을 만족하지 못하면 유효한 완전 계획이 아니다.
- 연중 전체 공백인 사람의 빈 참여 목록·빈 결과는 기존처럼 허용한다. 가용량이 있는데 참여 목록이 비어 있으면 완전 계획이 아니다.
- 선택하지 않은 사업에 자동 할당하지 않는다. 기간 밖·제외 월의 월별 할당은 0이다.
- 사람별 월 합계와 사업별 연간 목표를 동시에 만족하는 월별 해가 있어야 한다. 연간 합계와 사업별 단독 용량만 확인해서는 부족하다.
- 모든 사람·사업을 함께 고려한다. 상한에 걸리면 그 사람이 선택한 다른 사업으로 가능한 만큼 재분배하며 전체 선호의 균형을 고려한다.
- 실행 가능한 해가 있는데 단순 탐욕 배분이나 입력 순서 때문에 불가능하다고 판정해서는 안 된다. 동일 입력은 항목 순서와 무관하게 같은 결과를 내야 한다.

연간 할당량은 가능하면 소수 둘째 자리 값을 사용하고, 필요하면 `0.00001` 단위까지 허용한다. 계산은 `Decimal`·5자리 단위 정수와 기존 반올림 원칙을 사용하며 float를 쓰지 않는다.

계획의 연간 목표는 위 조건 안에서 조정할 수 있다. 반면 실적작업의 입력된 연간 목표는 알고리즘이 바꾸지 않는다.

### 월별 알고리즘과의 경계

[실적작업의 기존 월별 알고리즘](allocation-algorithm.md)은 변경하지 않는다. 월 기준, 휴직의 실제 일수 비례, 사업 기간의 월 전체 허용, 제외 월, 완전 균등 우선·편차 조정·분기 말월 나머지 배치를 그대로 사용한다.

계획의 연간 최소 참여 `0.01000`과 월별 최소 배정 목표 `0.00010`은 별개다. 월 최소 배정 완화의 `W006`만으로 확정 내보내기를 막지 않는다. 월별 엔진·검증 재사용은 가능하지만 업무 화면·자료·실행 순서를 하나로 묶지 않는다.

## 실적작업 사용 절차

1. 실적작업 모드를 선택한다.
2. 사용할 사업 파일과 이미 정해진 연간 할당량의 사람 파일을 불러온다. 계획에서 내보낸 파일뿐 아니라 외부에서 정한 값이나 연중 수정된 자료도 가능하다.
3. 입력 탭에서 사업 조건·연간 할당량·휴직 등을 확인하고 필요한 경우 사용자가 직접 수정한다.
4. 결과 탭에서 기존 엔진의 월별 할당·검증·요약·상세를 확인한다.
5. 오류가 있으면 입력을 고쳐 다시 계산한다. 계산 과정에서 연간 할당량을 임의 변경하지 않는다.
6. 필요하면 기존 엑셀 저장 등을 사용한다. 기존 CLI 실적 계산도 유지한다.
7. 다음 계획이 필요하면 모드를 전환한다. 전환 자체가 실적 파일을 계획 파일로 변환하지 않는다.

실행 방법은 [README의 GUI 안내](../README.md#gui)를 따른다. 계획 파일을 실적 모드에 직접 열면 계획 모드에서 열도록 안내하며, 실적 파일을 계획의 일반 불러오기에 주면 명시적인 계획 준비 명령을 사용하도록 안내한다.

## 저장·내보내기와 자료 보호

### 계획 저장: 중단·재개

```text
계획작업_2027/
  projects.yaml
  plans/
    plan_2027.yaml
```

현재 사업 자료와 `stage: planning` 사람 자료를 함께 보존한다. 사람 자료에는 `draft`, 선택적 `priorities`, 현재 `allocations`, 휴직 등이 들어간다. 미계산·합계 불일치·상한 초과 등도 저장할 수 있으며 결과 확정을 뜻하지 않는다. 저장을 이유로 값을 자동 보정하거나 문제가 있는 항목을 버리지 않는다.

### 계획 내보내기: 검증된 결과 확정

```text
확정자료_2027/
  projects.yaml
  people/
    people_2027.yaml
```

- 계획에 사용한 현재 사업 파일과 확정 사람 파일을 별도 폴더에 함께 저장한다. 사업 파일의 종료 사업·과거 연도 기록도 보존한다.
- 확정 사람 파일은 `year`, `stage: confirmed`, 사람 이름·필요한 휴직·확정 `allocations`를 쓴다. `draft`, `priorities`, `draft_allocations`는 쓰지 않는다.
- 오류가 있는 현재 결과는 내보내지 않는다. 경고만 있으면 설명과 함께 허용한다.
- 계획 작업 자료와 기존 실적 자료를 자동 덮어쓰지 않는다. 사업·사람 파일이 서로 다른 시점의 내용으로 섞인 상태를 성공으로 처리하지 않는다.
- 모드별 수정 상태 유지, 닫기 확인과 기존 첫 덮어쓰기 `.bak` 백업 등 자료 보호 원칙을 유지한다. Ctrl+S는 계획 중간 저장(실적 모드에서는 기존 입력 저장), Ctrl+Shift+S는 내보내기다. 창을 닫을 때 두 모드의 미저장 변경을 모두 확인한다.
- 계획 저장·확정 묶음 내보내기는 모든 파일을 대상 폴더의 임시 파일에 먼저 준비한 뒤 교체한다. 교체 중 실패하면 이미 바꾼 파일을 역순 복구하고 새 파일은 제거한다. 복구도 실패하면 원본 복구용 임시 파일의 경로를 오류로 알리고 남긴다. 정전·프로세스 강제 종료까지 보장하는 디스크 트랜잭션은 아니다.
- 확정 내보내기는 두 모드에서 불러온 원본·현재 계획 작업 파일과 동일한 사업·사람 경로로 쓰는 것을 막는다. 내보내기는 계획 중간 저장이나 실적 입력 변경을 대신하지 않는다.

## 이전 구현에서 변경한 내용

아래 표는 이전 계획 구현에서 이번에 바뀐 부분을 설명한다. 이전 파일의 결과·참여 정보는 호환 변환으로 보존한다.

| 항목 | 이전 구현 | 현재 구현 |
| --- | --- | --- |
| GUI | 좌측 입력·결과·계획 | 상단 모드 선택, 모드별 입력·결과 |
| 이전 실적값 활용 | 이전 확정 참여율을 계획 시작값으로 복사·참조하지 않음 | 직전 파일에서 연도·단계·키를 바꿔 참고값으로 사용 가능 |
| 참여 목록·선호 | `priorities` 필수 | `draft`로 참여 목록과 기본 순위, `priorities`는 선택 |
| 계획 결과 키 | `draft_allocations` | `allocations`로 결과 저장, `draft`는 별도 입력 참고값 |
| 두 단계 가중치 | 정확히 두 사업 특례, `1,1,3`은 `2,2,1` | 단계 수가 둘이면 `3:2`, `1,1,3`은 `3,3,2` |
| 계획 연도 배정 누락 | 기존 참조·목표에 따른 검사 | 계획 연도 수행 사업 전체의 배정인력 필수 |
| 확정 생성 | 계획 파일 유지, 확정 사람 파일 생성 | 별도 폴더로 사업·확정 사람 파일 묶음 내보내기 |

**기존 `draft_allocations`를 새 `draft`로 단순 이름 변경하면 안 된다.** 기존 키는 결과이고 새 `draft`는 참고값이다. 기존 파일이 `priorities`만으로 참여 목록을 표현하면 해당 목록과 명시 순위를 유지하고 새 참고 점수는 모두 0으로 두며, 기존 `draft_allocations` 결과는 새 `allocations`로 옮긴다. 재계산은 새 가중치를 사용하되 보관된 수동 결과는 자동 변경하지 않는다.

로더는 이전 형식 변환을 W007로 알리고, GUI는 변환 안내와 미저장 표시를 한다. 저장하면 새 형식으로 쓴다. 새·옛 결과 키를 혼합하거나 새 `draft`와 옛 `draft_allocations`를 함께 쓰면 오류다. 기존 설정에 함께 보관된 파일 목록은 최초 실행 시 파일 종류를 보고 두 모드의 목록으로 분리한다.

### 기존 계산 구현의 참고 경계

현재 계획 엔진은 최소 `0.01000` 참여와 사람·월 가용량·사업 상한을 정수 흐름으로 함께 검사한다. 선호 균형은 개인 가용량으로 정규화한 희망값과의 제곱편차를 최대 `0.05` 단위 등의 볼록 구간별 선형 비용으로 근사한다. 정확한 제곱편차의 전역 최적값은 보장하지 않는다.

현재 2자리 선택은 완전한 5자리 해를 얻은 뒤 최대 나머지 방식으로 **한 후보**를 만들고 월별 검증을 하는 방식이다. 모든 2자리 해의 존재를 탐색·증명하지 않는다. 이 문서도 그보다 강한 보장을 새로 합의한 것으로 보지 않는다. 불가피함을 증명하지 않았다면 `5자리 사용`이라고만 안내한다.

완전한 해가 없으면 기존과 같이 최소 참여를 풀고 전체 배정량 최대의 부분 초안·개인별 부족량·원인을 표시하며 확정 내보내기를 막는다. 새 파일·UI에서도 이 기능을 유지한다. 부분 결과도 상한·허용 월·비음수·5자리 단위를 위반해서는 안 된다.

## 구현 세부 결정과 남은 검증 경계

1. 빈 순위는 점수 방식, 점수에 별도 업무 상한 없음, 이전 파일은 참고 점수 0·기존 순위와 결과 보존으로 구현했다. 저장 형식은 예전 결과를 참고값으로 오인하지 않도록 선택했다.
2. 편집 중 잘못된 점수·순위·결과·날짜 문자열과 계산 제약 오류는 중간 저장·복원할 수 있다. YAML 문법 오류·중복 키·mapping/list 구조 불일치는 가져오기에서 거부한다. 잘못된 문법 자체를 정상 파싱해 보존한다는 뜻이 아니다.
3. 결과 형식 오류가 있어도 재계산 시 참고 입력을 별도로 검증하고 덮어쓰기 확인 뒤 결과를 다시 만들 수 있다. 입력 변경 때 현재 결과를 재검증하며, 결과 탭에 들어가기만 해서는 계획 결과를 재계산하지 않는다.
4. 두 작업은 별도 작업 위젯·문서·설정 목록을 갖는다. 사업 표와 실적 결과 표를 기존 위젯으로 재사용하지만 데이터 객체는 공유하지 않는다. 부분 초안·균형 목적 함수·결정적 동률 처리·2자리 후보의 기존 보장 범위는 위와 같다.
5. 소스 회귀·offscreen GUI·네이티브 Windows Qt 점검의 실제 결과와 미검증 업무 규모·운영체제·저장장치 경계는 세션 기록에 남긴다. 배포용 실행파일은 사용자가 명시적으로 요청할 때에만 빌드한다.

실제 작업과 검증 경계, 다음 할 일은 [SESSION.md](../SESSION.md)의 최신 관련 항목을 따른다. 과거 기능별 작업 이력은 [개발 기록](development-log.md)에 유지한다.

실적/확정 사람 파일은 선택 fixed 월별 고정값을 지원한다. 이는 계획 파일의 필드가 아니며 계획 모드에서 fixed를 입력하면 미지원 오류다. 실적에서 다음 연도 계획을 준비할 때는 이전 allocations를 참고 점수로 복사하되 fixed는 옮기지 않고 GUI 상태 안내에 표시한다. 계획의 월별 검증에서 만드는 Person은 기본 fixed={}이며 기존 계획 산정 규칙은 유지한다.
