# 연간 인력 계획 기능 명세 및 구현 인계

> 상태: **GUI 계획 기능 구현**. 2026-11-04 사용자 협의 내용을 기준으로 한다. CLI의 월별 계산은 [기존 월별 배분 명세](requirements.md)를 따르며, 계획 파일은 GUI의 계획 화면에서 연다.

## 목적과 경계

현재 프로그램은 사람이 사업별 **확정 연간 목표**를 입력하면 그 값을 바꾸지 않고 월별로 배분한다. 계획 기능은 새 연도의 목표를 정하기 전에 사람별 참여 사업과 우선순위를 입력받아 연간 참여율 **초안**을 만든다. 사용자는 사람 × 사업 표에서 이를 조정한 뒤 기존 월별 검증을 통과하는 확정 사람 파일을 만든다. 2026년 확정값을 2027년 계획의 시작값으로 복사하거나 참조하지 않는다.

사업의 `yearly.<연도>.allocated_manpower`는 **상한**이며 전부 소진할 필요가 없다. 계획에서도 기존의 `projects.yaml`, 사업 기간, 제외 월, 휴직의 일수 계산, 월별 기준량과 5자리 단위를 그대로 사용한다. 그래프·CSV는 이 기능에 포함하지 않는다. Windows GUI 실행파일 빌드는 [README](../README.md#windows-단일-실행파일)를 따른다.

## 사용자와 합의한 동작

1. 사람마다 참여할 사업을 직접 고르고 각 사업에 정수 우선순위를 직접 입력한다. 같은 순위를 여러 사업에 줄 수 있다. 선택한 사업에는 작게라도 참여율을 주며 최소 목표는 **각각 `0.01`**이다.
2. 우선순위는 높은 순위일수록 더 큰 **초기 비중**을 뜻한다. 서로 다른 두 순위의 예는 `0.60/0.40`(3:2), 세 순위의 초기 가중치는 3:2:1이다. 같은 순위 사업은 같은 가중치를 받는다. 이는 상한이나 월별 제약이 없는 경우의 기준이며 최종값을 고정하지 않는다.
3. 사업별 상한을 넘을 상황이면 그 사업의 참여율을 줄이고, 해당 사람이 선택한 다른 사업에 가능한 만큼 재분배한다. 사람 목록 순서로 먼저 확정하지 않고 전체 사람의 선호를 함께 고려한다. 연간 초안이 월별 수행 기간·제외 월·휴직과 충돌하면 연간 목표를 재조정한다.
4. **연간 참여율은 가능하면 소수 둘째 자리**까지 쓴다. 휴직과 허용 월 등 때문에 불가피하면 기존의 `0.00001` 단위까지 허용한다. 월별 결과는 원래대로 5자리다.
5. 모든 제약을 만족하는 완전한 초안이 없으면 가능한 부분 초안, 사람별 미배정 인력, 충돌한 사업 상한·허용 월 등의 원인을 보여 준다. 미완성 초안은 확정 파일로 내보내지 않는다.
6. 왼쪽 메뉴에 별도 **계획** 화면을 둔다. 계획 화면에서 초안을 생성하고 사람 × 사업 종합표의 참여율을 직접 수정한다. 한 칸을 바꿔도 다른 칸은 자동으로 바꾸지 않는다. 사람 총합 부족·초과, 사업 상한 초과, 월별 배분 문제를 표의 색과 설명으로 보여 준다. 기존 확정 단계의 종합표는 읽기 전용이다.
7. 계획과 확정 파일은 별도로 유지한다. 계획에서 수동으로 고친 초안도 계획 파일에 저장하여 다음에 이어서 수정한다.

## 파일 계약

계획 파일 기본 위치는 `plans/plan_2027.yaml`이다. `year`가 계산 연도를 결정하며 파일명은 안내용이다. `priorities` 키는 기존 사업 `alias`를 참조한다. `draft_allocations`가 없으면 초안을 아직 생성하지 않은 상태다. 생성 뒤에는 선택한 사업의 현재 연간 초안값만 저장한다. 부분 초안과 사용자가 고쳐서 검증 오류가 있는 값도 계획 파일에 저장할 수 있다.

```yaml
year: 2027
stage: planning
people:
  - name: 홍길동
    priorities:
      사업1: 1
      사업2: 2
    draft_allocations:
      사업1: "0.60000"
      사업2: "0.40000"
  - name: 김철수
    absences:
      - period: "2027-07-01~2027-09-30"
    priorities:
      사업1: 1
      사업2: 1
```

확정 파일 기본 위치는 `people/people_2027.yaml`이다. `stage: confirmed`를 새 파일에 쓴다. 기존 파일은 `stage`가 없어도 확정 파일로 읽어야 한다. 확정 파일에는 우선순위와 초안값을 쓰지 않고 기존 `allocations`를 사용한다.

```yaml
year: 2027
stage: confirmed
people:
  - name: 홍길동
    allocations:
      사업1: "0.60000"
      사업2: "0.40000"
```

계획 파일은 `priorities`가 필수이고 `allocations`는 받지 않는다. 확정 파일은 `allocations`가 필수이고 `priorities`·`draft_allocations`는 받지 않는다. `draft_allocations`의 키는 그 사람의 `priorities`에 있는 사업만 허용한다. 모든 별칭의 공백 처리·중복 검사, 휴직 형식, 수량 검사는 기존 데이터 모델을 따른다. 우선순위는 불리언이 아닌 양의 정수로 제한한다. 중복 YAML 키를 덮어쓰지 않는다. 사업 파일과 사람 파일의 연도가 다른 사업 연도 정보는 기존 규칙대로 다룬다.

계획 파일에 초안이 없는 상태와, 선택 사업의 초안값이 `0.00000`인 상태를 구분한다. `0`은 부분 초안이나 수동 편집 중에는 저장할 수 있으나, 가용량이 있는 사람이 선택한 사업에 `0.01` 미만을 받은 채 확정할 수는 없다. 연중 전체 휴직으로 사업 가용량이 0인 사람의 빈 참여 목록은 기존 `allocations: {}`와 같은 방식으로 허용한다.

## 초안 생성·검증 계약

`B_m`·월별 휴직량 `A[i,m]`·가용량 `C[i,m]`은 [월별 계산 명세](allocation-algorithm.md)와 동일하게 구한다. 사람 `i`의 연간 배분 가능량은 `1.00000 - Σ_m A[i,m]`이다. 사업 `p`의 연간 합계는 상한 `U[p]` 이하이며, 선택하지 않은 사람·사업과 기간 밖·제외 월의 월별 값은 0이다. 완전한 초안에서는 모든 사람·월의 사업 합계가 `C[i,m]`이고, 선택한 각 사람·사업 목표는 최소 `0.01`이다. 사람·사업 연간 목표는 월별 결과를 합산한 값과 일치해야 한다.

초기 희망값은 그 사람의 연간 가용량을 순위 가중치로 비례 배분해 구한다. **합의된 예시**는 서로 다른 순위의 사업 두 개가 3:2, 세 개가 3:2:1이다. 따라서 **선택 사업이 정확히 두 개이고 순위가 서로 다를 때만** 3:2를 쓰고, 그 밖에는 서로 다른 순위가 `k`개면 높은 순위부터 `k, k-1, …, 1`로 일반화한다. 같은 순위 사업마다 같은 가중치를 부여하며, 숫자 순위의 빈 간격은 비중에 영향을 주지 않는다. 예: `1, 1, 3`의 사업 가중치는 `2, 2, 1`이다. 이 특례는 두 사업 3:2 합의와 `1, 1, 3` 예시를 동시에 지키기 위한 선택이다. 나머지 일반화·빈 간격 처리는 구현을 위한 명시적 기본값이며 별도 사용자 합의 사례는 아니다.

초안 생성기는 모든 사람·사업·월을 함께 보아야 한다. **완전한 해가 있는데 탐욕적 순서 때문에 실패했다고 판정해서는 안 된다.** 우선 0.01 최소 참여와 월별 제약을 만족하는 완전한 해를 찾고, 그 안에서 희망 비중에 가까운 초안을 선택한다. 연간 목표가 소수 둘째 자리인 후보를 우선 시도하고 월별 검증을 통과하지 못하면 5자리 단위로 재시도한다. 두 자리 후보가 없다는 사실을 확인하지 못했다면 5자리 사용 이유를 단정하지 말고 단지 사용한 정밀도를 표시한다. 결정적 동률 규칙을 정해 YAML 항목 순서나 실행 순서로 결과가 달라지지 않도록 한다. 계산은 `Decimal` 또는 5자리 단위 정수로 하고 float를 사용하지 않는다.

### 구현 목적 함수와 정밀도 선택

완전한 해의 **존재 판정**은 사람·월 가용량, 선택 사업, 사업 상한, 선택 사업별 최소 `0.01000`을 함께 넣은 정수 흐름으로 한다. 그 해들 사이의 선호 균형은 사람별 희망값 `D[i,p] = C[i] × w[i,p] / Σw[i,*]`와 실제 연간 목표 `T[i,p]`의 정규화 차이 `((T[i,p] - D[i,p]) / C[i])²`의 합을 기준으로 한다. 구현은 각 사업 목표축을 최대 `0.05` 단위와 희망값 경계로 나눈 **볼록 구간별 선형 비용**으로 이 기준을 근사한다. 따라서 제곱편차의 정확한 전역 최적값을 보장하지 않는다. 동률은 사람 이름·사업약칭·월 오름차순의 흐름 간선 순서로 재현한다.

완전한 5자리 흐름을 얻은 뒤 사람별 연간 목표를 `0.01` 단위로 최대 나머지 방식으로 반올림하여 **2자리 후보**를 만든다. 사람의 연간 가용량이 `0.01`의 정수배가 아니면 이 후보는 만들 수 없다. 후보의 선택 사업 최소값·사업 상한·공용 월별 엔진 검증을 모두 통과하면 2자리 초안을 쓴다. 그렇지 않으면 원래 5자리 흐름 목표를 쓰고 `5자리 사용`이라고만 표시한다. 이 후보 시도는 2자리 해 전체의 완전 탐색이나 존재 증명이 아니다.

완전한 해가 없을 때는 최소 참여 조건을 풀고 **전체 배정량 최대**인 흐름을 먼저 구한다. 같은 최대량의 해에서는 위 구간별 비용, 이어 사람 이름·사업약칭·월 순서로 결정한다. 이 결과에서 `0.01` 미만인 선택 사업을 별도로 표시한다. 입력 순서를 바꿔도 같은 결과를 내며, 부분 초안을 완전한 해로 표시하지 않는다.

완전한 해가 없을 때의 부분 초안은 가능한 배정량을 최대화하되 상한·허용 월·비음수·5자리 단위는 지킨다. 사람별 부족량은 `연간 가용량 - 부분 초안의 연간 사업 합계`로 표시한다. 최소 참여가 불가능한 선택 사업도 따로 표시한다. 부분 초안은 **확정 결과가 아니라 수정용 참고값**이다. 초안 생성 결과와 사용자가 편집한 현재 값은 같은 검증 함수를 거쳐 사람 합계, 사업 상한, 최소 참여, 월별 실행 가능성을 판정한다. 오류가 남아 있으면 확정 파일 생성 버튼을 비활성화한다. 경고만 있으면 설명과 함께 생성할 수 있다.

## GUI 상세

왼쪽 메뉴 `계획`은 기존 `입력`·`결과`와 독립된 화면이다. 선택 연도와 사업 입력은 공유하되 계획 사람 문서와 확정 사람 문서는 각각 별도로 보관한다. 계획 화면에서 사람 목록을 선택하면 참여 사업·순위 편집 표와 휴직 편집 표가 나타난다. 참여 사업은 해당 연도에 배정이 있고 기간이 겹치는 사업을 고를 수 있게 하며, 현재 등록되지 않은 별칭은 지우지 않고 오류로 표시한다. `초안 생성`, `계획 저장`, `확정 파일 만들기` 동작을 구분한다.

종합표의 행은 사람, 열은 사업이며 참여율 셀만 편집한다. 선택하지 않은 사업의 교차 셀과 합계·공백·상한·잔여 칸은 읽기 전용이다. 사업 열에는 할당 합계·상한·잔여를, 사람 행에는 사업 합계·공백·총합을 고정된 위치에 표시한다. 초안이 없는 셀은 빈칸으로 두어 계산된 0과 구분한다. 수량은 기존 화면과 같은 5자리 문자열로 표시한다. 잘못된 수량 형식은 해당 셀, 사람 총합 문제는 사람 합계, 상한 초과는 사업 합계를 우선 강조하고 툴팁·검증 목록에 차이와 조치 방법을 적는다. 한 문제의 영향 셀은 함께 찾을 수 있게 표시하되 색만으로 의미를 전달하지 않는다. 편집 직후 합계를 갱신하고, 월별 실행 가능성은 공용 엔진의 판정으로 갱신한다.

초안이 이미 있거나 수동 변경이 있으면 `초안 생성` 전에 현재 값을 덮어쓴다는 확인을 받는다. 계획 저장은 오류가 있는 값도 보존하며 내보내지 않은 변경 표시와 기존 백업 정책을 적용한다. 확정 파일 만들기는 현재 표의 값으로 기존 `load_inputs`·월별 엔진 검증을 통과한 경우에만 가능하다. 계획 파일은 보존하고 확정 파일만 별도 생성한다. 확정 파일 생성 뒤에도 계획 화면의 우선순위·초안은 유지한다. 기존 확정 사람 입력과 결과 화면은 현재 규칙을 유지한다.

## 월별 엔진 변경과 계획 기능 (2026-11-06)

월별 엔진은 완전 균등 배정을 먼저 찾고, 불가능하면 `0.00010` 하한을 지키며 편차를 줄인다. 하한도 모두 지킬 수 없을 때만 셀별 부족량을 최소화하고 예외 월을 W006으로 알린다. 이 규칙은 계획의 **연간** 최소 참여 `0.01`과 별개다. 계획의 초안 검증·확정 생성은 같은 월별 엔진을 사용하고, W006 경고만으로 확정 생성을 막지 않는다.

## 구현 순서와 경계

1. 계획 YAML 로더·문서 모델·직렬화와 확정 `stage` 호환성을 구현한다. 기존 CLI에서 `stage` 없는 파일의 계산 결과가 같아야 한다. 계획 파일을 월별 CLI에 직접 주면 계획 단계 파일이라는 명확한 오류를 낸다.
2. 순수 계산 모듈로 초안 생성·부분 초안·진단을 구현한다. 기존 월별 엔진의 공백량·허용 월 계산을 재사용하고, 계산 완료 뒤 공용 사후 검증을 사용한다. 계획 GUI만 별도의 수치 규칙을 갖지 않게 한다.
3. 계획 화면과 편집 가능한 종합표, 저장·재열기·확정 파일 생성 흐름을 붙인다. 기존 확정 화면과 입력 파일의 동작을 회귀 검증한다.
4. 성능·오프라인 설치를 확인한다. 새 의존성이 필요하면 버전과 오프라인 wheel 준비·설치 방법을 문서화한다.

## 수용 사례

| ID | 입력·행동 | 기대 결과 |
| --- | --- | --- |
| P01 | 휴직·상한 충돌 없이 한 사람, 사업1 순위 1·사업2 순위 2 | 초안 `0.60000`·`0.40000`, 월별 계산 통과. |
| P02 | 한 사람, 사업1·사업2 같은 순위 1 | 같은 초기 비중; 정확한 총합과 월별 계산. |
| P03 | 순위 `1, 1, 3` | 같은 순위 두 사업의 초기 가중치는 같고 셋째는 그 절반. |
| P04 | 여러 사람이 사업1 상한을 함께 초과하려는 경우, 각자 대체 사업 있음 | 전체 사업1 합계는 상한 이하, 넘는 인력은 각자의 선택 사업으로 재분배. 사람 파일 순서를 바꿔도 같은 결과. |
| P05 | 사업 상한보다 실제 합계가 작음 | 정상; 남은 상한을 표시하고 사업 목표를 억지로 채우지 않음. |
| P06 | 휴직·부분 사업 기간·제외 월로 월별 제약이 충돌 | 연간 목표를 재조정해 가능한 해를 찾거나, 없으면 부분 초안·사람별 부족량·충돌 원인을 표시. |
| P07 | 선택 사업 최소 0.01을 모두 줄 수 없음 | 최소 참여 실패를 설명하고 확정 파일 생성을 막음. |
| P08 | 종합표에서 한 칸을 바꿔 사람 총합 부족 또는 사업 상한 초과 | 다른 칸은 그대로, 관련 합계와 셀·검증 목록에 문제 표시; 오류 상태 계획 저장 가능. |
| P09 | 수동 수정한 계획 저장·재열기 후 초안 재생성 | 값이 보존됨; 재생성 전 덮어쓰기 확인. |
| P10 | 유효한 계획을 확정 파일로 생성 | 계획 파일 유지; 새 확정 파일은 기존 월별 CLI·GUI에서 읽고 계산 가능. 기존 `stage` 없는 파일도 그대로 읽힘. |
| P11 | 계획 파일을 확정 입력으로 읽거나 단계와 다른 필드·중복 키·잘못된 순위 입력 | 위치와 원인을 가진 오류, 조용한 값 삭제·덮어쓰기 없음. |
| P12 | 초안의 2자리 연간 목표로 월별 제약을 만족하지 못하지만 5자리 목표로 가능한 경우 | 5자리 초안과 정밀도 안내, 월별 합계·사업 상한 모두 통과. |

## 다음 세션에서 확인할 사항

사용자와 **직접 합의한 규칙**은 위 `사용자와 합의한 동작` 절이다. `draft_allocations`라는 정확한 키 이름, 순위 빈 간격의 처리, 부분 초안의 동률 처리, 계획 화면의 구체적인 배치·색상은 구현을 가능하게 하기 위한 기본값이다. 2자리 후보는 한 번 구성하여 공용 월별 엔진에서 검사한다. 2자리 해 전체를 탐색하지 않으며, 구간별 비용은 정확한 제곱편차 최적화를 보장하지 않는다. 성능과 실제 창 조작의 검증 경계는 `SESSION.md`에 기록한다.
