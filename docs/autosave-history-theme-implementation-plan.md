# 실시간 YAML 저장·실행 이력·테마·메타데이터 구현 계획서

## 1. 목적과 승인 범위

작성일: 2026-11-28. 기준 소스: main `1e620f295c8486221787e4a608b3fcbce7f23eee`.

사용자는 이 대화에서 검토한 기능을 계획서로 정리하고 **Terra 모델에게 구현과 테스트를 맡기도록 요청했다**. 이전의 “아직 구현하지 마”는 요구사항 수집 중의 지시였으며, 이번 요청으로 아래 범위의 구현·소스 테스트를 승인한 것으로 전달한다. EXE 빌드·Git 커밋·푸시·PR·병합은 승인 범위가 아니다.

### 합의한 기능

1. 밝은/어두운 테마에서 이름·압정·배경·선택·격자·오류·경고 등을 읽기 쉽게 개선한다.
2. 입력·결과 화면의 **업무 데이터 변경**을 관리 중인 사업·사람 YAML에 실시간 저장한다. 사람·사업 입력 순서 변경도 포함한다.
3. 실행 취소/다시 실행은 단축키로 한 단계씩, 메뉴의 짧은 이력을 통해 여러 단계씩 이동한다. 이동한 상태도 파일에 반영한다.
4. 종료하면 실행 이력만 초기화한다. 파일의 최신 저장 내용은 유지한다.
5. 숫자 칸의 문자 입력은 막는다. 숫자 형식은 맞지만 제약·합계 등이 틀린 값은 저장하고 오류를 알린다.
6. 별도 수동 저장 메뉴를 없애고 자동 저장 상태를 표시한다. 다른 위치/이름의 사본은 내보내기로 만든다.
7. 사람·사업의 `metadata` 아래에 자유 정보를 보관하고 계산에는 사용하지 않는다. 자동 저장·실행 이력·내보내기에서 보존한다.

### 구현 금지 및 자료 보호

- 계산 알고리즘, Decimal/정수 수량, 월·연간 목표, 계획 순위 가중치, fixed 계약을 임의 변경하지 않는다.
- 소스 테스트는 임시 파일·임시 QSettings만 사용한다. 실제 `myteam/**`와 사용자 설정은 변경하지 않는다.
- 시작 시 `myteam/people/people_2026.yaml`의 사용자 수정과 미추적 `.bak`이 있다. 수정·복구·삭제·테스트 입력 변형 금지.
- 기존 `SESSION.md` 로컬 기록을 유지한다. 사용자 업무 파일이 테스트 순회에 들어가면 파일을 고치는 대신 테스트 대상을 격리한다.
- EXE 빌드, 의존성 자동 갱신, 네트워크 기반 실행 기능 추가, Git 게시 금지.
- 구현·검증 결과는 한국어로 보고한다. 테스트 예정·추정은 완료가 아니다.

## 3. 기존 명세와의 충돌 및 변경 원칙

1. **수동 저장/dirty 기반 안내 → 자동 저장**: 기존 요구사항·README·테스트는 수동 저장을 전제한다. 새 명세로 갱신하되 실제 I/O 실패·원본 미지정 상태의 보호 경고까지 없애지 않는다.
2. **미지원 필드 → metadata만 공식 확장 허용**: 현재 계산 로더는 알 수 없는 필드를 E003으로 처리하고, 실적 GUI는 dropped로 안내한 뒤 재저장 시 제거할 수 있다. `metadata`는 명시적으로 허용·보존하되 그 밖의 오타·미지원 필드는 계속 검출한다.
3. **오류 자료 저장과 확정은 분리**: 업무 제약 오류는 저장할 수 있지만 결과 계산의 ERROR·확정 내보내기 차단은 유지한다. YAML 문법 오류나 중복 키를 “오류도 저장”의 근거로 자동 덮어쓰지 않는다.
4. **숫자 입력 차단은 GUI 입력 지원**: 계산 검증을 새로 만들지 않는다. 외부 파일에 이미 들어 있는 잘못된 값을 조용히 삭제하거나 자동 보정하지 않는다.
5. **계획 중간 저장과 확정 내보내기는 다르다**: 내보내기 메뉴 안에서도 작업자료 사본과 실적용 확정 묶음을 구분한다.
6. **결과 표시 순서와 업무 문서 순서는 다르다**: 현재 결과 상세 드래그는 임시 표시/복사 순서이고 YAML 입력 순서를 바꾸지 않는다. 단순 선택·스크롤·글꼴·보기 전환을 업무 변경으로 저장하지 않는다. 결과 상세 순서까지 입력 원본 순서로 영구화하는 새 규칙은 사용자가 명시하지 않았으므로 기존 의미를 유지하고 이 경계를 보고한다. 이 경계를 바꿔야 한다고 판단되면 먼저 질문한다.
7. `.bak`과 실행 이력은 별개다. 실행 이력은 세션 내 되돌리기이며 `.bak`은 기존 첫 덮어쓰기 백업 정책을 유지한다.

각 변경 이유를 관련 명세와 SESSION에 함께 남긴다. 필수 보호 규칙과 충돌하면 조용히 해석하거나 테스트를 삭제하지 말고 사용자에게 알린다.

## 4. 구현 설계 기본값과 질문이 필요한 경계

아래는 미확정 세부사항을 막연하게 방치하지 않기 위한 **계획서의 보수적인 기본값**이다. 원본 이전·데이터 삭제·호환성 파괴를 수반하는 대안은 사용자 확인 없이 선택하지 않는다.

### 4.1 문서와 저장 대상

- 사업 문서와 모드·연도별 사람/계획 문서에 원본 경로, 읽기/쓰기 인코딩, 최근 성공 저장 지문, 추가정보, 필요한 원본 소속 정보를 연결한다. 내부 식별자는 허용하지만 YAML ID를 요구하지 않는다.
- 단일 원본은 그대로 갱신한다. **불러오기 자체는 파일을 쓰지 않는다.**
- 새 문서·새 연도 등 원본이 없으면 저장 위치를 명시적으로 지정받는다. 취소 시 디스크 변경 없이 자료를 잃지 않도록 하고 “저장됨”으로 표시하지 않는다. 위치 결정 전 편집을 허용할지 막을지는 일관된 UX로 정해 문서화한다.
- 내보내기는 사본 생성이다. 기본적으로 원본 경로·인코딩·자동 저장 대상을 바꾸지 않는다. 사용자가 명시적으로 다른 파일을 다시 불러오면 새 원본으로 작업한다.
- 여러 파일을 합쳤을 때 기존 항목 변경은 가능한 한 **그 항목이 속한 원본**에 반영한다. 이름·alias가 바뀌거나 삭제되어도 소속을 잃지 않게 추적한다. 새 항목은 대상 원본이 불명확하면 한 번 명시적으로 선택한다.
- 여러 파일 사이의 전역 순서는 각 YAML 목록만으로 표현되지 않을 수 있다. 여러 원본에 전체 합친 내용을 복제하거나 원본을 비우지 않는다. 출처를 넘나드는 순서 저장에 통합 파일이 필요하면 적용 전에 사용자에게 **통합 위치/원본 유지 정책을 질문**한다. 단일 원본 기능을 먼저 구현할 수 있으나 다중 원본 경계를 숨기거나 전체 완료로 보고하지 않는다.
- 2026-11-28 사용자 결정: 서로 다른 원본에 걸친 순서 변경과 다중 원본 상태의 새 사람·사업 추가는 통합 파일을 새로 만들고 원본을 유지한다. 통합 파일 경로와 이름은 실제 통합 시 지정한다.
- 같은 물리 파일을 두 모드/두 창이 열었을 때 stale 문서로 덮어쓰지 않도록 별도 확인이 필요하다. 자동 모드 변환이나 두 모드 문서 공유로 독립성을 깨지 않는다.

### 4.2 자동 저장 트랜잭션

- 작업 전/후 업무 문서 스냅샷 또는 검증된 command 객체를 사용한다. 입력 delegate가 확정하기 전의 키 입력마다 저장하지 않는다.
- 셀 편집 완료, 다중 셀 붙여넣기, 삭제, 사람/사업 추가·삭제·개명, 참여 사업 변경, 날짜·휴직 변경, 제외월/연도 배정 변경, 입력 순서 이동, 고정 토글, 계획 수동 결과 및 명시적 계획 계산을 공용 작업 경계로 연결한다.
- 약칭 변경 등 여러 사업/연도/사람 파일에 영향을 주는 작업은 한 묶음이다. **모든 대상의 인코딩 준비 → `write_bundle` 교체 → 메모리/이력 확정** 순서를 공용 서비스에서 보장한다. 기존 결과 압정도 이 경로로 합쳐 이중 저장을 없앤다.
- 신호 재진입, 초기 불러오기, 화면 재그리기, 계산 결과 표시, Undo/Redo 재생은 새로운 저장·이력을 재귀적으로 만들지 않는다.
- 저장 성공 후에만 정상 작업의 이력 커서를 이동하고 저장 지문을 갱신한다. 변화가 없는 작업은 파일도 이력도 건드리지 않는다.
- 일반 저장 실패는 파일/화면/선택/이력 커서를 작업 전 상태로 복구하고 이유·경로를 알린다. 인코딩 전환 거절도 취소와 같다.
- 디스크 복구까지 실패하면 실제 디스크 상태를 성공으로 표현하지 않는다. 복구 파일·경로를 보존하고 해당 문서의 추가 자동 쓰기를 멈추며 해결 안내를 제공한다.
- 원본이 읽기 이후 외부 수정·삭제되었으면 덮어쓰기를 멈추고 재불러오기/사본 보존 등 안전한 선택을 제공한다. mtime만으로 성공을 가정하지 말고 내용 지문을 사용한다.
- 실행 중 파일 감시를 쓴다면 자기 저장을 외부 수정으로 오인하지 않고, 외부 변경을 감지한 경우 오래된 Undo가 그 내용을 덮지 않게 한다. 외부 편집은 이번 실행 이력의 작업으로 합성하지 않는다.
- `.bak`, CP949/EUC-KR/UTF-8(BOM), 표현 불가 문자 확인, 복구 파일 보존은 기존 정책을 유지한다. 정전·프로세스 강제 종료까지 다중 파일 원자성을 보장한다고 주장하지 않는다.

### 4.3 수정 오류 안내와 숫자 편집

- 잘못된 합계·상한 초과·고정 합계 불일치 등 수정 중 자료를 YAML에 저장하고 오류를 알린다. 셀/사람 표시·툴팁·검증 목록/상태바를 재사용하고 매 키 입력마다 팝업을 띄우지 않는다.
- 숫자 칸에서 알파벳·한글 등 숫자 형식이 아닌 새 입력은 차단한다. 금지 문자를 조용히 제거해 다른 수치로 만들지 않는다.
- 편집 중 빈칸·`0.` 등 중간 상태를 허용한다. 확정 시 중간 상태가 그대로 남으면 원문을 보관·저장하고 기존 검증으로 안내하며 조용히 0으로 바꾸지 않는다.
- 소수 6자리, 범위 밖 값, 날짜 오류 등 기존 검증을 통과하지 못하는 자료도 보존 가능한 작업 자료다. 이를 반올림하거나 범위 안으로 강제 조정하지 않는다.
- Decimal 수량, 정수 순위/연도, 제외월 목록의 입력 문법은 구분한다. 날짜 입력의 `-`·`.`·기존 날짜 선택 UI를 숫자 전용 필터로 망가뜨리지 않는다.
- 붙여넣기에서 문자 등 입력 형식이 맞지 않는 대상이 있으면 **전체 작업을 적용하지 않고** 문제 위치를 알린다. 헤더·표 밖·읽기 전용 셀을 처리하는 기존 범위 정책은 유지한다. 유효한 숫자이나 논리 오류인 값은 붙여넣고 저장한다.
- 외부 파일의 오류값은 조회·수정할 수 있어야 한다. 새 문자 입력을 차단한다는 이유로 이미 존재하는 값이 사라지면 안 된다.
- 현재 `dump_people`가 빈 참여율을 생략하는 등 원문 보존과 충돌하는 경로를 검토하고, **유효한 삭제 명령**과 **미완성 셀 입력**을 구분해 데이터 손실을 막는다. 재열기에서도 오류 자료가 같은 상태로 돌아와야 한다.

### 4.4 실행 취소/다시 실행

- 기본값: 앱의 업무 작업을 **전역 시간순 이력**으로 관리하되 각 작업에는 모드·연도·문서·화면 맥락을 기록한다. 한 모드의 작업은 그 모드 자료만 바꾸며 관련 사업/사람 참조 변경은 한 작업으로 묶는다.
- 모드/연도 탐색·탭 전환은 이력을 지우거나 추가하지 않는다. 되돌리는 작업의 대상 모드·연도를 알 수 있도록 필요한 화면으로 이동하고 선택을 안정적으로 복원한다.
- 단축키 Ctrl+Z/Ctrl+Y는 업무 작업 한 단계. 아직 확정하지 않은 셀/이름 편집기 안에서는 텍스트 편집기의 로컬 Undo와 앱 이력이 동시에 실행되지 않게 처리한다.
- 하나의 붙여넣기·드래그·일괄 고정·사람 삭제·약칭 변경·계획 재계산은 각각 한 작업이다. 자동 재검증과 화면 갱신은 별도 작업이 아니다.
- Undo 뒤 새 작업이 성공하면 Redo 분기를 제거한다. 실패·취소·무변경 작업은 Redo를 없애지 않는다.
- 메뉴는 `실행 취소`/`다시 실행` 하위의 최신 순 이력이다. 예: `실적·사람 입력 — 참여율 수정`, `계획·결과 — 할당 수정`, `실적·사업 입력 — 순서 변경`. 필요하면 짧은 사람/사업명·연도를 넣되 긴 값 목록은 피한다.
- 메뉴에서 N번째 항목을 선택하면 그 사이의 연속 N개 작업을 취소/재적용한다. 특정 작업만 골라 중간 작업을 건너뛰는 selective undo는 아니다.
- **여러 단계 이동은 목표 상태 한 번을 저장하는 하나의 묶음**으로 처리한다. 실패하면 전체 이동을 취소하고 기존 이력 커서를 유지한다.
- 많은 항목은 메뉴 스크롤/더 보기와 줄임표로 제한한다. 화면 밖으로 잘리거나 항목 폭이 무제한으로 커지지 않게 한다. 최근 20개 표시 후 더 보기 등 구현 방식은 선택 가능하나 숨겨진 이력을 삭제해서는 안 된다.
- 이력에는 업무 스냅샷·순서·metadata·관련 인코딩 메타정보 등 복원에 필요한 데이터를 넣고, 암호 등 원문값을 메뉴에 노출하지 않는다.
- 종료 후 이력을 저장/복원하지 않는다. 프로그램 재실행 시 빈 이력에서 시작한다.
- 새 파일 열기/교체·문서 닫기·새로 만들기는 이력의 대상 객체를 무효화할 수 있는 경계다. 유효하지 않은 옛 파일에 Undo가 쓰지 않도록 영향을 받는 이력을 안전하게 정리하고 안내한다. 파일을 연 행위 자체로 파일 내용을 재작성하지 않는다.

### 4.5 메뉴와 저장 상태

- 상단 파일 메뉴의 수동 `저장` 및 Ctrl+S의 종전 폴더 저장 동작을 제거한다. Ctrl+S를 누른다고 매번 내보내기 창을 띄우지 않는다.
- `내보내기`는 작업자료 사본 저장과 기존 계획의 검증된 확정 내보내기를 구분한다. 오류 자료 사본은 가능하지만 확정 묶음과 정상 결과 엑셀은 기존 검증 경계를 유지한다.
- 폴더 묶음 내보내기와 함께 단일 파일의 다른 이름 저장 요구도 충족할 수 있게 대상 선택 UI를 설계한다. 임의로 파일명을 고정해 “다른 이름” 기능이 있다고 주장하지 않는다.
- 상태바에 원본 경로와 `저장 중`/`저장됨`/`저장 위치 필요`/`저장 실패`/`외부 변경 충돌`을 명확히 보인다.
- 정상 저장된 변경에 dirty 별표나 반복 저장 확인을 표시하지 않는다. 미지정·실패·취소 자료에 대한 종료 보호는 유지한다. “오류 N건, 저장됨”처럼 업무 검증과 디스크 저장 상태를 구별한다.
- 종료·모드 전환·내보내기 전 활성 편집기를 확정/취소하는 정책을 일관되게 적용하고, 화면에 보이는 마지막 값이 빠지지 않도록 검사한다.

## 5. metadata 확장 계약

### 위치와 의미

- 최소한 개별 사업, 실적 사람, 계획 사람에 선택적 `metadata` mapping을 허용한다. 파일 공통 정보를 위해 최상위 `metadata`도 일관되게 허용·보존하는 것을 설계 기본값으로 한다.
- 그 안에는 사용자 정의 키와 일반 YAML 데이터(문자열·수치·불리언·null·목록·하위 mapping)를 보관할 수 있다. 날짜/전화번호/사번처럼 표현 자체가 중요한 값은 따옴표 문자열 사용을 안내한다.
- 계산·순위·가용량·정렬 기준으로 metadata를 자동 해석하지 않는다. 전용 GUI 편집기·검색·메타정보 기반 계산은 후속 범위다.
- metadata 밖의 미지원 키는 계속 검출한다. `allocatons` 같은 오타를 확장정보로 취급하지 않는다.

### 보존·보안·호환

- 로드/자동 저장/내보내기/Undo/Redo/사람·사업 개명 및 이동에서 사용자 추가정보가 항목과 함께 따라가야 한다.
- 기존 문서 모델이 metadata를 버리지 않도록 읽기·문서 보관·쓰기·계획/확정 변환 경로를 모두 변경한다. 계획 준비/사본/확정 변환에서는 대응하는 사람·사업·파일 공통 metadata를 보존하되 `fixed`의 자동 복사 금지는 유지한다.
- 안전한 YAML 처리만 사용한다. 사용자 정의 객체 태그·실행 태그를 허용하지 않는다. 중복 키 검사는 metadata 내부에도 적용한다. 순환 참조 등 직렬화가 안전하지 않은 자료는 명확히 거부하고 파일을 쓰지 않는다.
- 수량 원문용 `Number`를 float로 바꾸거나 무조건 문자열로 직렬화해 metadata 숫자의 타입/정밀도를 훼손하지 않는다. 필요하면 안전한 노드/스칼라 태그 보관 방식을 사용해 테스트한다.
- 주석·들여쓰기·따옴표 방식·anchor의 원문 그대로 보존까지 이번 범위로 약속하지 않는다. 보존 대상은 데이터 의미·키/값/자료형·사용자가 의도한 문자열과 정밀도다.
- 기존 미지원 필드가 metadata 밖에 있는 파일은 기존 GUI의 dropped 후 자동 저장으로 정보가 사라지지 않게 **파괴적 자동 저장을 차단하고** metadata로 옮기도록 안내한다. 불러왔다는 이유로 필드를 삭제하지 않는다.
- “어떤 정보든”은 안전한 YAML 데이터 안에서의 자유라는 뜻이며 임의 객체 실행이나 문법 오류 허용이 아니다.

- 시스템 고대비/강제 색상 모드에서는 사용자 지정 팔레트보다 접근성 정책을 우선한다. 구현 플랫폼에서 지원하지 못하면 정확한 경계를 보고한다.
- 런타임 테마 전환 시 기존 열린 창·delegate·아이콘·메뉴를 다시 반영한다.

## 7. 단계별 구현 순서

1. **기준 확인**: Git diff/사용자 파일 상태를 기록하고 기존 테스트를 격리된 자료로 실행한다. 현재 실패와 신규 실패를 구분한다.
2. **명세 갱신과 충돌 보고**: 위 변경을 README/요구사항/데이터 모델/검증/수용 사례/계획 문서에 맞추고, 안전한 기본값으로 해결 못 하는 지점은 질문한다.
3. **보존 기반**: metadata·오류 원문·문서 소속·스냅샷을 구축하고 왕복 테스트부터 통과시킨다. 추가정보가 유실될 수 있는 상태에서 자동 저장을 먼저 켜지 않는다.
4. **저장 기반**: 공용 트랜잭션/인코딩/복구/외부 충돌·원본 대상 결정을 구현하고 단위 테스트한다.
5. **업무 이력**: 단일 작업과 여러 단계 이동을 파일 트랜잭션에 연결한다. 결과 고정과 입력 이벤트를 통합한다.
6. **UI 연결**: 자동 저장·오류 안내·숫자 입력·메뉴·단축키·상태·내보내기·종료 보호를 연결한다.
7. **테마 적용**: 공용 테마와 delegate를 수정하고 실제 선택 배경과 글자/압정의 결합 렌더링을 검사한다.
8. **전체 회귀 및 보고**: 새 수용 사례와 기존 CLI/계산/계획/인코딩 테스트를 실행하고, 원본 업무 파일을 건드리지 않았는지 확인한다.

단계별 별도 모듈/테스트 파일을 추가해도 되며 위 순서는 안전성을 위한 의존성이다. 구현 도중 담당하지 않은 파일 수정이 발견되면 덮어쓰지 않는다.

## 9. 완료 보고와 인계 조건

구현 담당자는 아래를 최종 보고한다.

1. 수정 파일과 기능별 구현 결과, 남은 기능/막힌 이유.
2. 선택한 세부 정책과 기존 명세를 바꾼 이유. 사용자에게 추가 확인한 결정.
3. 실제 실행 명령·환경·스타일, 테스트 수·통과/실패/skip, 신규 회귀 검증 내용.
4. 소스 기반 GUI 실행 방법. EXE가 갱신되지 않았음을 명시.
5. 실제 업무 YAML·사용자 설정을 변경하지 않았다는 확인.
6. 미검증 OS/DPI/실마우스/디스크 장애/고대비 경계.
7. `SESSION.md` 최신 항목에 실제 수행·결과·다음 작업을 기록.

모든 조건을 한 번에 충족하지 못하면 단계별 구현과 검증된 범위를 정직하게 보고한다. 안전 정책에 사용자 결정이 필요한 지점은 구현 완료로 처리하지 말고 질문/중간 보고한다.
