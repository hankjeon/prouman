# 자동 저장·이력 구현 독립 검토 — 2026-11-28

**최신 판정: 하단의 최종 소스 독립 검토 통과.** 최초 반려와 단계별 보완 증거는 아래에 그대로 보존한다. 실제 OS/장치 미검증 경계는 남아 있다.

## 최초 판정

**반려: 전체 요구사항 미구현.** 기존 회귀 통과만으로 기능 완료를 승인할 수 없다.

검토 대상은 `main 1e620f2` 위의 현재 미커밋 소스와 테스트, 신규 `history.py`다. 기존 Terra 채팅은 done 상태였으며 최종 응답에서도 전체 미완료를 명시했다. 이는 완료된 기능에 표시만 남은 문제가 아니다.

## 우선순위별 지적

### P1-01. 일반 입력·계획의 자동 저장이 없다

- `src/allocation/gui.py`의 `people_changed`, `projects_changed`, `plan_changed`는 여전히 dirty 상태만 설정한다.
- `refresh_marks`, `keep_all`, `closeEvent`가 별표와 수동 저장 요청을 계속 사용한다.
- 임시 단일 원본에서 참여율 `1`을 `0.9`로 수정한 뒤 이벤트를 처리했다. 메모리는 `0.9`, 디스크는 `1`, 파일 바이트는 변경되지 않았다.
- 오류인 합계도 작업자료에 저장하기로 했으므로 `0.9`의 논리 오류는 저장하지 않을 이유가 아니다.
- 단순히 별표나 종료 질문을 제거하면 데이터 유실이다. 먼저 실제 저장과 복구를 연결하고 성공/실패/미지정 상태를 구분해야 한다.

### P1-02. 업무 Undo/Redo가 GUI·파일에 연결되지 않았다

- `src/allocation/history.py`의 `History`는 독립 단위 테스트만 있다.
- 현재 업무 위젯/메인창에 이를 연결하는 import·작업 경계·명령이 없고 Ctrl+Z/Ctrl+Y 및 이력 메뉴가 없다.
- 여러 셀 변경·복수 파일 약칭 변경·고정 토글의 단일 작업화, N단계 이동의 최종 묶음 저장, 실패 시 커서 복구를 제품 경로에서 검증해야 한다.

### P1-03. 저장 메뉴·내보내기·저장 상태 계약이 바뀌지 않았다

- 실제 `MainWindow` 파일 메뉴에 `저장`/Ctrl+S가 남아 있다.
- 정상 자동 저장 상태·사본 저장·다른 이름·계획 확정 내보내기를 합의대로 연결하지 않았다.
- 신규 문서/다중 원본 통합 파일 UI가 없다. 사용자가 이미 선택한 “통합 파일 새로 생성·기존 원본 유지” 정책을 구현해야 한다.
- 일반 저장/내보내기는 `write_yaml_jobs`를 지문 없이 호출할 수 있어 결과 압정에만 추가된 외부 충돌 보호가 전체 업무 경로를 포괄하지 못한다.

### P1-04. 전체 수용시험의 증거가 없다
