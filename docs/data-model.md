# YAML 데이터 모델

## 공통 규약

- 입력 파일은 YAML이며 인코딩은 UTF-8(BOM 허용)을 권장한다. UTF-8로 해석할 수 없으면 CP949(Windows 한글 ANSI, EUC-KR 포함)로 다시 읽는다. 사업 파일과 사람 파일은 서로 다른 인코딩이어도 된다. 두 인코딩 모두로 해석할 수 없으면 `E001`이다. 한글이 든 UTF-8 파일은 CP949로 잘못 해석되지 않지만 그 반대는 가능하므로 UTF-8을 항상 먼저 시도한다. 같은 mapping 안의 중복 키는 파싱 시 `ERROR`다. 날짜는 따옴표로 감싼 문자열로 입력한다. 연도는 4자리, 월·일은 1~2자리이며 `-` 또는 `.`로 구분한다. 점 구분 날짜의 마지막 점은 선택 사항이다. `date`로 실제 달력 유효성을 검사한다.
- 인력 수치는 인용한 5자리 이하 소수 문자열을 권장하며, 파서가 읽은 YAML 숫자도 **float를 거치지 않고 원문에서 Decimal로** 변환할 수 있을 때만 허용한다. 지수 표기·NaN·무한대·음수·소수 5자리 초과는 거부한다. 표시는 언제나 소수 5자리다.
- 연도 키는 4자리 정수, 월은 정수다. 알 수 없는 필드·잘못된 자료형은 조용히 무시하지 않고 `ERROR`로 보고한다. 선택 필드의 기본값은 문서에 명시한 것만 적용한다.
- 관리 연도 `year`와 `yearly` 연도 키는 `1000~9999`의 정수다. 연도와 월에 불리언을 허용하지 않는다.

## 기간의 날짜 형식

사업 `period`와 휴직 `absences[].period`에 같은 규칙을 적용한다. 아래 표기는 모두 같은 기간이다.

```yaml
period: "2026-01-01~2026-12-31"
period: "2026-1-1~2026-12-31"
period: "2026.1.1~2026.12.31"
period: "2026.1.1.~2026.12.31."
```

위 네 줄은 대안 표기 예시이므로 실제 mapping에는 `period`를 한 번만 쓴다. 시작일과 종료일은 각자 다른 허용 표기를 써도 된다. 예: `"2026.1.1.~2026-12-31"`. 내부에서는 모두 동일한 `date` 값으로 계산한다.

한 날짜 안에서는 구분자를 섞지 않는다. 슬래시, 날짜 안의 공백, 하이픈 날짜의 끝 점은 허용하지 않는다. 없는 날짜(예: `2026.2.29`)와 시작일이 종료일보다 늦은 기간은 표기와 관계없이 오류다.

## 이름과 사업약칭의 공백 처리

- 사업명(`projects[].name`)은 문자열의 앞뒤 공백을 제거한다. 중간 공백은 허용하며 그대로 유지한다. 예: `"  연구 지원 사업  "` → `"연구 지원 사업"`.
- 사업약칭(`projects[].alias`)은 앞뒤 공백을 제거한 뒤 내부에 공백이 있으면 `ERROR`다. 예: `"  사업1  "` → `"사업1"`, `"사업 1"` → `ERROR`.
- 여기서 공백은 일반 스페이스뿐 아니라 탭·줄바꿈 등 Python의 `str.strip()`과 `str.isspace()`가 인식하는 공백 문자다. 제거 후 빈 사업명·사업약칭은 `ERROR`다.
- `allocations`의 사업약칭 키와 CLI `--project` 인자에도 같은 사업약칭 규칙을 적용한다. 약칭 중복 검사, 참조, 정렬, 출력은 앞뒤 공백을 제거한 값으로 처리한다. 서로 다른 원문 키가 공백 제거 후 같아져도 중복 오류이며 합산하거나 덮어쓰지 않는다.
- 사람 이름은 공백만 있는 문자열을 거부하되 나머지는 입력 그대로 비교한다. 사업명·사업약칭 이외의 문자열을 자동으로 정규화하지 않는다.

## `projects.yaml`

```yaml
projects:
  - name: 사업1
    alias: 사업1
    period: "2026-04-15~2028-09-10"
    yearly:
      2027:
        allocated_manpower: "1.50000"
        excluded_months: [4, 5, 6]
      2028:
        allocated_manpower: "1.00000"
        excluded_months: [0, 0, 0]

  - name: 사업2
    alias: 사업2
    period: "2025-01-01~2029-12-31"
    yearly:
      2027:
        allocated_manpower: "1.50000"
        excluded_months: []
```

| 필드 | 규칙 |
| --- | --- |
| `projects` | 비어 있지 않은 필수 목록. 각 사업의 `name`과 `alias`는 위 공백 처리 규칙을 따른다. `alias`는 사업 간 고유한 식별키다. YAML에 사업 `id`를 입력하지 않는다. |
| `period` | 필수 문자열 `시작일~종료일` (아래 날짜 형식 참고). 시작일 ≤ 종료일. 다년 사업 가능. 경계일은 포함한다. |
| `yearly` | 필수 mapping: 연도 → 해당 연도의 사업 정보. `{}` 및 특정 연도 항목 누락은 허용한다. 수행 기간 밖의 연도 정보는 경고한다. |
| `yearly.<연도>.allocated_manpower` | 해당 연도 배정인력 **상한**. 0 허용, 음수 금지. |
| `yearly.<연도>.excluded_months` | 선택 제외 월 배열. 생략하면 `[]`로 처리한다. 생략, `[]`, `[0]`, `[0, 0, 0]`은 제외 월 없음. 명시할 때는 배열이어야 하며 `null`은 허용하지 않는다. 0은 자리 채움 값으로 무시한다. 나머지 값은 1~12. 같은 제외 월 반복은 경고 후 한 번만 적용한다. |

사람 파일의 `allocations`는 `alias`로 참조한다. 내부 ID가 필요하면 프로그램이 관리하고 YAML 작성자에게 요구하지 않는다. `allocated_manpower`는 배분해야 할 목표가 아니라 **상한**이다. `excluded_months`는 해당 사업의 할당 가능 월만 줄이며 연간 배정인력 값이나 사람의 연간 목표량을 바꾸지 않는다. 초기 대화의 `id`, `start_date`/`end_date`, 별도 `yearly_manpower` map, 제외 월별 `reason`은 뒤의 간소화 합의에서 대체되었다.

## `people/people_2027.yaml`

```yaml
year: 2027
people:
  - name: 홍길동
    allocations:
      사업1: "0.60000"
      사업2: "0.40000"

  - name: 김철수
    absences:
      - period: "2027-07-01~2027-09-30"
    allocations:
      사업2: "0.75000"
```

위 두 파일을 함께 사용하면 홍길동은 두 사업에 합계 `1.00000`, 김철수는 3분기 전체 공백 `0.25000`과 사업2 목표 `0.75000`을 가진다. 사업1의 4~6월 제외 조건과 사업별 배정 상한까지 만족하는 배분이 가능하다. 별도의 배분 불가능 사례는 [test-cases.md](test-cases.md)에 둔다.

| 필드 | 규칙 |
| --- | --- |
| `year` | 필수, `1000~9999`의 정수. 한 번의 실행에서 계산할 연도이며 파일명의 연도보다 우선한다. |
| `people` | 비어 있지 않은 필수 목록. `name`은 비어 있거나 공백만으로 이루어질 수 없고 파일 내 고유하다. |
| `absences` | 선택 목록. 생략 또는 `[]`이면 공백 없음. 여러 기간 허용. |
| `absences[].period` | 필수 문자열 `시작일~종료일` (아래 날짜 형식 참고). 시작/종료일 포함. 시작일 ≤ 종료일. |
| `absences[].reason` | 선택 문자열. 계산에 영향을 주지 않는다. |
| `allocations` | 필수 mapping: 사업 별칭 → 고정 연간 할당량. 공백 처리 후 참조 별칭이 사업 파일에 존재해야 한다. `{}`는 허용하되 연간 합계 검증을 통과해야 하므로 연중 전체 공백인 사람만 정상이다. |

연간 할당량은 사람마다 한 번만 기재한다. 사람별 `yearly` 묶음, 월별 12개 숫자 배열, 인력 ID 참조는 앞선 제안에서 쓰였지만 1차 최종 입력 형식이 아니다. 공백 사유를 쓰지 않아도 동일하게 계산한다.

## 내부 계산 값

`base[month]`: 월 기준 인력, `absence[person,month]`: 반올림한 월 공백 인력, `capacity = base - absence`, `target[person,project]`: 입력 연간 목표, `x[person,project,month]`: 출력 월별 할당. 출력 집계는 `x`의 합으로 계산하고 YAML에 중복 저장하지 않는다. 모든 값은 0.00001 단위의 비음수 값이다.
