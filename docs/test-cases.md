# 수용 테스트 사례

실제 테스트는 임시 YAML을 생성해 CLI와 계산 함수를 검증한다. **기대 수치는 5자리 고정 소수 문자열**로 비교하고, 연간 합계만이 아니라 월별·분기별 제약도 확인한다. 모든 성공 사례에서 동일 입력 반복 및 YAML 사업/사람 순서 변경 후 결과가 같아야 한다.

| ID | 입력 요점 | 기대 결과 |
| --- | --- | --- |
| T01 | 2027년, 연중 사업1 상한 1, 사람 1명, 사업1 목표 `1.00000`, 공백 없음 | 사업1 월별 값은 1·2월 `0.08333`, 3월 `0.08334` 패턴을 분기마다 반복. 분기 `0.25000`, 연간 `1.00000`. |
| T02 | 연중 사업1·사업2, 사람 1명, 사업1 `0.60000`, 사업2 `0.40000`, 공백 없음 | 사업1은 매월 `0.05000`, 사업2는 `B_m - 0.05000`으로 간단히 균등 배분 가능. 모든 월·연간 합계가 정확하고 입력 순서와 무관하다. |
| T03 | 사업1은 4~6월 제외, 사업2는 연중. 사람 1명 사업1 `0.60000`, 사업2 `0.40000` | 4~6월 사업1=`0.00000`, 사업2=`B_m`. 사업1은 나머지 9개월에 `0.06666`/`0.06667`로 균등 분할 가능하고 사업2는 월별 잔여량을 채운다. 두 사업의 연간 목표와 모든 월 합계가 정확하다. |
| T04 | 사업1은 `2027-04-15`~`2027-09-10`, 사업2는 연중. 공백 없는 사람의 목표 사업1 `0.50000`, 사업2 `0.50000` | 사업1은 4~9월 각각 `B_m` 전량, 3월·10월 0. 사업2는 나머지 6개월 전량. 4월·9월에 수행 일수 비례 상한을 적용하지 않는다. |
| T05 | 2026년 7월 15~31일 공백(17일), 연중 사업1 목표 `0.95430` | 7월 공백 `0.04570`, 사업1 가용 `0.03763`; 연간 공백 `0.04570`, 사업1 연간 `0.95430`, 합계 `1.00000`. |
| T06 | 2028년 2월 29일 하루 공백, 연중 사업1 목표 `0.99713` | 2월 공백 `ROUND_HALF_UP(0.08333/29)=0.00287`; 연간 사업1 `0.99713`. 윤년 29일 적용. |
| T07 | 같은 사람의 2027-07-01~07-10 및 07-05~07-15 공백, 연중 사업1 목표 `0.95968` | `WARNING` 중복, 7월 공백 일수 15일(20일 아님), 공백 `0.04032`, 정확한 월·연간 합계. |
| T08 | `2026-12-20~2027-01-10` 공백을 year 2027에 사용, 연중 사업1 목표 `0.97312` | `WARNING` 연도 밖 기간, 2027년 1월 1~10일만 반영해 1월 공백 `0.02688`. |
| T09 | 공백 없음, 한 사람 사업 목표 합계 `0.90000` 또는 `1.10000` | 각각 부족/초과 `ERROR`, 최종 표 없음, 실패 종료. |
| T10 | 공백 `0.04570`인데 사업 목표 `1.00000` | 공백+목표 `1.04570`로 `ERROR`; 목표 자동 축소 없음. |
| T11 | 연중 사업1만 목표 `1.00000`, 사업1의 4~6월 제외 | 연간 합계는 1이지만 제외 월 가용량을 채울 사업이 없어 배분 불가 `ERROR`. |
| T12 | 사업1·사업2가 모두 4~6월 제외, 공백 없는 한 사람의 목표 사업1 `0.50000`, 사업2 `0.50000` | 각 사업의 단독 허용 월 용량은 `0.75000`이지만 공동 허용 월 용량은 `0.75000`뿐이므로 `ERROR`. |
| T13 | 두 사람의 사업1 연간 목표 합 `1.20000`, 사업1 배정상한 `1.00000` | `ERROR`, 초과 `0.20000`. 상한보다 적은 경우 정상. |
| T14 | 사업1 대상 연도 배정 0/미등록, 양수 목표 없음 | `WARNING`, 다른 입력 유효하면 계속. 양수 목표가 있으면 `ERROR`. |
| T15 | 사업 별칭 중복, 사업 정식명 누락, 사람 이름 중복, 할당 별칭 미존재, YAML 같은 키 반복 | 각각 `ERROR`. 중복 키가 뒤의 값을 덮어쓰면 실패. YAML 사업 ID는 입력하지 않는다. |
| T16 | 날짜 `2027-02-29`, 역전 기간, 소수 6자리, 음수, NaN, 제외 월 13 | 각각 `ERROR`; 반올림·자동 수정 없음. |
| T17 | `absences` 생략 vs `[]`, `reason` 생략, `yearly: {2027: {allocated_manpower: "1.00000", excluded_months: [0, 0, 0]}}` | 각각 명세대로 정상. 같은 입력의 계산 결과 동일. `[0, 4]`는 4월만 제외. |
| T18 | `--person`, `--project`, `--all`, 존재하지 않는 이름/별칭 | 지정 표에 월·연간 합계와 공백/배정/잔여 표시. 미존재 대상은 명확한 오류. |
| T19 | `excluded_months: [4, 4]` 및 사업 기간 밖의 `yearly` 등록 | 각각 `WARNING`. 중복 4월은 한 번만 제외하고 기간 밖 연도에는 할당하지 않는다. |

## 계산 검증 방법

T02·T03은 각 사람·사업의 연간 목표뿐 아니라 **모든 월의 정확한 합계와 허용 월의 값**을 검사한다. 제곱편차의 최솟값이나 다른 실행 가능한 해보다 더 균등한지까지 검사하지 않는다. 같은 입력을 반복하고 YAML의 사업·사람 순서를 바꾸어도 같은 결과가 나와야 한다. T11·T12는 간단한 분할의 성공 여부가 아니라 실제 배분 가능성에 따라 오류를 판정하는지 확인한다.

T06의 정답은 `0.08333 / 29 = 0.002873...`이므로 `0.00287`, 따라서 연간 가용량은 `0.99713`이다. T05의 7월 공백 `0.04570`과 T06의 2월 공백 `0.00287`은 윤년·정밀도 회귀 검사다. 실제 사람·사업 수가 늘어난 경우에도 정수 단위의 제약 검증을 모든 결과에 적용한다.
